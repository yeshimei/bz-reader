# 原型 · 划词 AI 浮卡加三档（解释 / 翻译 / 摘要）

**一次性原型，不是产品代码。** 要回答的问题只有一个：

> 点工具条上的「AI」把划线发给 AI，卡片里怎么让用户在「解释 / 翻译 / 摘要」之间切换，
> 而又不把卡片撑成一张表单？

先说清楚它和侧栏 AI 的分工：**这是两条路**。工具条的 AI 只发选中的那一段，
不发全书依据、不建索引、不带多轮历史；侧栏的 AI 反过来，一律按全书回答。
以后改哪边都不该牵动另一边。

## 打开

双击 `index.html`（单文件，无外部依赖）。底部控制条可以切：

- **视口**：桌面 / 手机
- **主题**：纸色 / 墨色
- **选项样式**：A 下划线 / B 分段（这一版要看的就是这两种做法的差别）
- **版本**：高级版 / 基础版（基础版里翻译、摘要上锁，点一下只提示去解锁）

页签、复制 / 重试 / 存为笔记都能真点：切档会走一次「请求中」的骨架态再出答案，
切换时上一次的结果立刻让位（真机上对应「取消上一个请求」）。

## 定下来的几条

1. **三档是同一张卡里的三个问法，不是三个入口。**
   同一段原文、同一张浮卡、同一个位置，切一下就地换答案——不重开卡片、不换弹层。
2. **默认停在「解释」。** 划完词点 AI，十次里有八次是想知道这句什么意思。
   翻译与摘要是「这次特意要」的动作，需要多一次点击是对的。
3. **页签放在原文下面、答案上面。** 顺序是「问的是哪段 → 怎么问 → 答案」。
   放卡片底部会和「复制 / 重试」抢位置，放顶部又会被当成标题。
4. **原文引用只留两行**（`-webkit-line-clamp:2`）：切档时要能确认问的是哪句，
   但不能让它把答案挤下去。
5. **切换即刻作废上一个请求**，不做并排两条。真机上连点两次档不该花两份钱。
6. **基础版只给解释**，另外两档留着可见但按下去只提示——藏起来等于告诉用户
   「这软件没有翻译」，摆着才知道高级版差在哪。
7. **不做记忆。** 每次划词都回到解释，避免上次切到摘要、这次一问就答非所问。
   （如果你更想要「记住上次那一档」，改一行状态就行，这条待你拍板。）

## 两种选项样式

| | A 下划线 | B 分段 |
| --- | --- | --- |
| 观感 | 安静的阅读器，和书页最贴 | 更像工具，三档存在感更强 |
| 优点 | 不抢答案，卡片上半部分仍然很轻 | 一眼看出这是可切的三个选项 |
| 代价 | 弱窗口 / 深色下容易被忽略 | 12px 高的色块压在引文下面，略重 |

原型默认 A；把控制条切到 B 对比着看。

## 落到真代码（下一步，还没改）

- `src/shell/reader-cards.ts` 的 `aiCardHtml()` 加一行页签 + `data-act="aimode" data-v="explain|translate|summary"`；
  同时在 `AiCardInput` 里加 `mode`。
- `src/shell/actions.ts` 增 `case 'aimode'`：把 `overlay.mode` 换掉 → `repaint()`；
  `overlay.ts` 的 `runAiForOverlay()` 已经按 `kind|task|text` 记账，**换档会自动重发一次**
  （它已经会 `RT.aiAbort.abort()` 掉上一条），这条链路基本现成。
- 现有 `translate` 那个独立弹层（`overlayTranslate`）可以退役：翻译变成 AI 卡的一档，
  少一套 DOM、少一份样式。
- 高级版闸门：`can('ai')` 只管「能不能用 AI」；三档要按 `entitlement()` 再判一次，
  基础版只放 explain——闸门加在 `aimode` 这个动作里，不能只靠按钮不渲染。
