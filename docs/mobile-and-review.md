# 移动端布局与全库体检

> 2026-11-03。这一轮做了三件事：把手机上的界面真正铺开、把整个代码库和界面从头到尾过一遍、列出还能往哪儿走。
> 标记 `已修` 的条目当场改完了；`待办` 的条目留到下一轮。

---

## 一、移动端布局

### 1.1 先说一个必须知道的前提

改造之前，**手机打开插件看到的根本不是新界面**。

`plugin.ts` 的 `openStudy()` 里写着：

```ts
if (Platform.isMobile) {
  openShelfModal({...});   // ← 重写之前的老书架弹窗
  return;
}
```

桌面走新的「书房」ItemView，手机走 `ui/shelf.ts` 那套旧弹窗。目录同理走 `ui/toc.ts`。

也就是说，之前所有关于壳层的样式打磨，在手机上一点都没生效。这一轮先把这个岔路堵上：**手机上书房是一个全屏 Modal，渲染与桌面 tab 完全同一份代码**。

### 1.2 为什么手机用 Modal 而不是 tab

手机上 Obsidian 的 tab 栏是隐藏的，切视图要靠「侧滑抽屉 → 已打开的 tab → 点一项」。用户从书房点进一本书，想回书房要绕这么一圈，读完一本基本就卡死在里面了。

全屏弹窗一步返回，这是移动端阅读器的通行做法。代价是渲染逻辑得能被两处复用，所以把书房拆成了两层：

| 文件 | 职责 |
|---|---|
| `shell/study-surface.ts` | 怎么画（四页、事件委托、焦点与滚动保持） |
| `shell/study-view.ts` | 画在桌面 tab 里 |
| `shell/study-modal.ts` | 画在手机全屏弹窗里 |

`StudyView` 从 187 行瘦到 55 行，只剩「我是谁、我画在哪」。以后改界面只需要动 Surface 一处，不会出现「手机和桌面越长越不像」。

### 1.3 两条触发线，各管一件事

移动端样式单独成文件 `shell/styles/mobile.css`，排在最后加载（同特异性靠顺序取胜）。里面用两套条件：

```css
@media (max-width: 820px) { /* 结构：怎么摆 */ }
.bzs-shell.is-mobile { /* 手感：触摸目标、安全区、hover 残留 */ }
```

为什么不合成一套：

- **布局只该认宽度**。iPad 有 1024 的宽屏，不该被当成手机重排；而桌面把窗口拖窄、Obsidian 左右分屏，都该得到窄屏布局。
- **手感只该认设备**。iPhone 横屏 844px 不命中媒体查询，但它依然是触摸屏，依然需要 44px 点击区和刘海避让。

### 1.4 具体改了什么

**阅读页**

| 元素 | 桌面 | 手机 |
|---|---|---|
| 顶栏 | 10 个图标 + 书名 | 5 个（目录/书签/搜索/排版/更多）+ 书名 |
| 多余动作 | 直接摆在顶栏 | 收进「更多」原生菜单 |
| 底栏 | 章节名 + ‹ + 进度 + › + 百分比 + 剩余 | ‹ + 进度 + › + 百分比 |
| 进度轨高度 | 20px | 30px（这是拖动命中区，不是视觉粗细） |
| 作者名 | 显示 | 隐藏（一行放不下两行字，书名是唯一锚点） |
| 选区工具条 | 浮在选字上方 | 贴到底栏之上，避免拇指挡住 |

「更多」用的是 Obsidian 原生 `Menu`，不是自绘弹层——移动端宿主会把它渲染成底部动作面板，带安全区、带返回键关闭。菜单里 7 项：并排对照 / 对照书籍 / 朗读 / Book Map / 章节缩览 / 专注 / 帮助。

**书房**

- 头行从「标题 + 页签 + 按钮」一行改成两行：`order:3 + width:100%` 把页签挤到第二行，不动 DOM 结构，事件委托也不用改。
- 书库封面墙：`minmax(150px)` → `minmax(96px)`，390 屏三列、320 屏自动退两列。
- 继续阅读卡：封面缩小、按钮从右侧竖排改为整行铺开，书名截两行。
- 笔记：单列，卡片上的四个元信息允许换行。
- 统计：KPI 四列变 2×2，图表区单列，热力图保持 20 列（少一列就看不出色阶）。
- 设置：两列变单列，快捷键表两列变一列，分段控件允许折行。
- 右侧新增一颗 ×（`data-act="closestudy"`），因为全屏弹窗需要一个明确的关。

**弹层**：居中卡片改成底部抽屉——贴底、上圆角 18px、最大 92% 高、左右无边距。内容多（功能对照表 14 行）时能滚，视觉上也不再是「屏幕中间浮着一块」。

**真机手感**

- `env(safe-area-inset-bottom)`：iPhone 的 Home 指示条会吃掉底部 34px。
- `@media (hover: none)` 关掉悬停位移动效——触屏上 hover 会在点击后「粘住」，封面一直浮着，看起来像卡住了。
- `:active` 给 0.97 缩放 + 透明度，触屏没有 hover，按下必须给反馈。

### 1.5 实测

视口 390×844，宿主侧栏与 ribbon 收起（真机没有）：

| 项目 | 结果 |
|---|---|
| 书房 Modal | 390×844，圆角 0、内边距 0，头行 94px 且页签在第二行 ✓ |
| 书库列数 | `107.5px × 3`（三列）✓ |
| 阅读顶栏 | 11 个按钮里 5 个可见，无溢出 ✓ |
| 底栏 | 章节名隐藏、百分比保留、进度轨 192×30 ✓ |
| 弹层 | 390 宽、贴底（gapBottom 0）、上圆角 18px ✓ |
| 点书 | 书房弹窗自动收起 ✓ |
| 控制台 | 无异常 ✓ |

另外为了让移动端能在桌面上验收，加了 `localStorage['bz-reader:force-mobile'] = '1'`：置 1 后桌面也按手机形态跑。真机上调一个样式要打包、装手机、截图，一轮几分钟；桌面改个 localStorage 就能看。它只影响界面承载，不参与任何授权判断。

## 二、代码体检

### 2.1 已修（这轮当场改掉）

**① 移动端走的是旧界面**
见 1.1。这是最严重的一条：所有新界面的工作，手机用户一点都拿不到。

**② 授权可以被外部存储伪造**
`entitlement()` 是同步函数（`can()` 在每次重绘里调用），而 ECDSA 验签是异步的。于是旧实现把「验签结论」直接落盘：

```ts
// 旧
e.plan = payload.plan;   // 存进 localStorage
e.exp = payload.exp;
```

用户在控制台写一句 `{"license":"x","checkedTs":1,"exp":0}`，就是永久高级版——**连一枚真码都不需要**。

改成两层：

1. **只存码，不存结论**。`plan / exp / name` 全部从码里现解（附内存缓存，避免重绘时反复 `atob`）。
2. **启动时真验一次**。`revalidateLicense()` 验不过就清码退回基础版。因为 localStorage 只在加载时读一次（之后走内存 cache），运行期改它不生效；要生效就得重载插件，而重载又会再验一次。

实测四种情况：伪造码→被清空；真码→保留；运行期改成假码→不生效；改回真码→恢复。旧记录里的 `plan/exp/name` 字段不再被读取，也不会再被写入。

**③ 壳层根节点没有任何布局规则**
`.bzs-shell` 只在 tokens.css 里定义了变量，没有 `display` / `height`。桌面靠 contentEl 是 flex 容器勉强能用，但手机上的书房装在 Modal 里，父级高度是 auto，`flex:1` 直接失效——书房会塌成内容高度，底部跟着内容跑。已补上根节点与包裹层的 flex 列布局。

### 2.2 待办

**① 阅读会话只增不减**（`reader-view.ts:997`）

```ts
book.reading.sessions.push({ ...session, percent });
```

每次关书 push 一条，**没有任何裁剪**。一本书读两年、每天三次 ≈ 2000 条；书架二十本就够把 `bz-reader.json` 撑到几 MB。而 store 每次保存都重写整个 JSON（500ms 防抖），写盘成本随数据线性上涨。

不能直接砍掉——统计页的时长、热力图、连续天数全部从 `sessions` 汇总（`stats.ts`），砍了统计就错。建议保留最近 365 天（热力图最多回看 100 天），或按月聚合旧记录。

**② 死代码：8 个文件、2074 行**

`src/ui/` 下零引用的：`annot` `footnote` `note-list` `prefs-panel` `quote-card` `search-panel` `shelf` `toc`。

它们对应的样式还留在 `src/styles.css` 里。当前 `styles.css` 产物 174KB，其中约一半来自这批旧样式：

```
legacy  src/core/ui/tokens.css + src/styles.css   ≈ 3935 行
shell   src/shell/styles/*.css                     ≈ 4112 行
```

删掉之后产物能砍到 ~90KB。这不只是体积问题——`.bzr-heat`、`.bzr-btn` 这些旧类名会和新壳层抢样式，之前「热力图变白底」就是这么撞出来的。

**③ 19 处空 catch，其中一处会丢数据**

绝大多数是合理的（读不到文件就是没读过、解析失败就当空库）。但有一条不该吞：

```ts
await this.api.store.flush().catch(() => undefined);
```

关书时落盘失败（盘满、文件被锁、同步工具占着），用户不会得到任何提示，这一次的阅读进度就没了。至少该 `notify(..., 'error')` 一次。

**④ `can(_cap)` 忽略能力参数**

```ts
export function can(_cap: Cap): boolean {
  if (!proBuild) return false;
  return entitlement().unlocked;
}
```

10 个能力共用一把总开关。买断制下这是对的（买了就全开），但参数名带下划线说明它是个「看起来支持细粒度、实际没有」的接口。要么真的按 cap 分档（比如年费只给部分），要么把签名改成 `can()` 并把 `Cap` 只当文案键用——现在这个形状容易让人误以为可以单独关某一项。

**⑤ base/pro 双包**（已知，最后做）

商城只分发单个 `main.js`，现在「覆盖安装」那套上架即失效。合并方案已经定了：单包 + 运行时 gate。

### 2.3 建议

- `verifyLicense` 每次调用都 `importKey`（SPKI → CryptoKey），实测一次激活没问题，但启动验签是每次加载都跑的，缓存一下更省。
- `parseLicense` 没有 payload 长度上限。用户自己粘贴的码，DoS 意义不大，但顺手加个 `if (payloadBytes.length > 4096) return null` 不吃亏。
- `store.ts` 的 `looksValid()` 只校验 `books` 是不是数组。一条结构半坏的记录（比如 `reading` 缺失）会在渲染时抛在很远的地方。可以在加载时补一次 `normalize`。

## 三、界面体检

### 3.1 已修

**① 长书名把布局撑坏**

测试库那本《红楼梦（人文社权威定本彩皮版；国务院文化组批准，红研所校注；豆瓣读书 TOP250 首位…）》是个天然的压力测试：

| 位置 | 症状 | 修法 |
|---|---|---|
| 继续阅读卡 | 书名占 5 行，吃掉整个首屏 | 截两行（`-webkit-line-clamp: 2`） |
| 笔记分组头 | 书名占 8 行 | 单行省略（flex 子项配 `min-width: 0`，否则省略号不生效） |
| 笔记卡出处 | 「书名 · 章节」占 3 行，把按钮挤下去 | 单行省略 |

**② 排版面板的方向预览卡漏字**

预览卡里放的是真实书名。横排卡还能截；竖排卡（`writing-mode: vertical-rl`）的文字会一字一行排到底、直接漏出卡片边界。已给卡片加 `overflow:hidden`，竖排改成单列 + 裁切。

**③ 设置页分段控件被压成竖排**

「书页纸色」有六个选项（纸/墨/羊皮/苔/夜/跟随 Obsidian），桌面上靠 `flex:1` 平分一行；手机上一行塞不下，最后一个被压成两行字。已允许折行。

### 3.2 待办

**① `--t3` 的对比度不够**

```
--t3: var(--text-faint, #93939c)   // 浅色主题下约 3.0:1
```

这个色被用在大量 **10~11px** 的小字上：书卡下面的「佚名」「TXT · 今天 76%」、章节列表右侧的百分比、设置页的说明文字。WCAG AA 要求正文 4.5:1，它不达标——而且字号越小越难读，手机上尤其明显。

不必全改。**只把小字号处换成 `--t2`**（`--text-muted`，约 6:1）就能解决 90% 的观感问题，层级感靠字号和字距维持，不靠灰度。

**② 一半 CSS 是死的**

同 2.2②。删的时候要连带清 `src/styles.css` 与 `src/core/ui/tokens.css` 里不再被引用的部分，否则下次又会撞名。

**③ 依赖 hover 的可见性**

有若干信息只在 `:hover` 时出现（书卡的「已读完 / 收藏」角标、章节行的操作）。触屏没有 hover，这些内容在手机上等于不存在。已用 `@media (hover:none)` 关掉位移动效，但「只在 hover 出现的信息」还没逐个改成常驻。

**④ 空态与错误态各写各的**

书库空、搜索无结果、笔记无标注、统计无数据，这四处的空态文案与排版各不相同（有的用 `.bzs-empty`，有的直接拼一段 `<div>`）。建议统一成一个 `emptyState({icon, title, hint, action})`，否则以后加第五个页面又会多一套。

### 3.3 建议

- 弹层 `.bzs-scrim` 是 `absolute` 挂在壳内，而不是 `fixed` 挂到 body（除了 overlay-root 那条）。同时开两个弹层的路径目前走不通，但 `z-index` 只有一档（40）。加弹层前先想清楚层级规则，比事后调数值便宜。
- 没有 `:focus-visible`。键盘 Tab 走到按钮上时看不出焦点在哪——Obsidian 用户里键盘党比例不低。
- 数字没有统一等宽字体。统计页的时长、百分比在刷新时会左右抖。`font-variant-numeric: tabular-nums` 一行解决。

## 四、还能往哪儿走

按「用户能感知到的价值 ÷ 实现成本」排，用大白话说。

### 现在就该做（成本低，马上能感觉到）

1. **让手机能真的读下去**
   现在手机上点正文左右翻页、上下滑滚动、双指缩放都有，但**没有「翻到章末自动进下一章」的过渡**，读完一屏会停住，得自己滑。这是手机阅读最容易劝退的一处。

2. **书架按「最近在读」排**
   书多了以后，找上次读的那本要先扫一眼。顶部虽然有一张「继续阅读」卡，但只能放一本。

3. **划线的手感**
   手机上长按选字 → 弹出工具条 → 选颜色，三步。微信读书是「选中即划」。可以做成「选完自动按上次用的颜色划上，工具条只负责改色和写想法」。

4. **把「导出」做成一次点击**
   现在要先开弹层、看预览、再复制。常用的应该是「一键导出这本书的全部划线到 `书摘/书名.md`」，弹层留给「换个格式」。

5. **读完的仪式感**
   读完最后一页弹一张卡：打分 + 一句话。写进 frontmatter。成本几乎为零，但「读完」是用户记忆最深的时刻，也是晒图的高发点。

### 值得做（要花几天，但能撑起卖点）

6. **划线活同步成书籍笔记**
   现在的导出是「拍快照」，导出完就断了。活同步是「这本书在你的笔记里活着」——划线随时追加、进度随时更新，能被 Dataview 查到。这才是 Obsidian 用户愿意付钱的东西。

7. **跨书搜索先建索引**
   现在的实现是逐本开临时引擎扫、不建索引。书多的时候点下去要转十几秒。**收费的功能必须比免费的体验更好**——它现在是付费项，却比免费的书内搜索慢一个量级，这会被当成 bug 骂。要么先补索引，要么暂时别锁它。

8. **主题阅读**
   给一个主题（比如「习惯养成」），跨书把相关划线捞出来，拼成一份综述草稿。这是「第二大脑」真正兑现的地方，但要等索引做完。

9. **阅读目标与连续打卡**
   统计页已经有热力图，缺一个「今年读了多少本 / 连续多少天」的正面反馈。属于低成本高感知。

### 以后再说（有意思，但现在做不划算）

10. **多端进度同步**（要服务端，和「不联网」的定位冲突）
11. **书摘卡片模板市场**（先看有没有人真的在分享）
12. **AI 朗读替代系统 TTS**（音质好，但要花钱，和买断制冲突）
13. **PDF 支持**（工程量约等于再做半个引擎）

## 五、一句话总结

**代码的地基是好的**——原子写盘、幂等收尾、资源清理、事件委托都做对了，`as any` 是 0 处，注释里记着每个坑是怎么踩出来的。真正的问题不在「写得糙」，而在**两块历史包袱**：一半的旧界面代码还活着（手机上甚至在用），以及授权判定曾经可以被一句话改掉。

**界面在桌面上是完整的，在手机上今天才算真正可用**。接下来最该补的不是新功能，是「手机读完一章会自动接下一章」这种最基础的手感。
