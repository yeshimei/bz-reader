## 零、修订（2026-11-07 下午，覆盖下文冲突条目）

同一晚连着改了两轮，下面五条以**本节为准**，正文里对应段落按「历史」读：

| 原来的条目 | 改成 | 原因 |
|---|---|---|
| §1.1 设置里有「AI 知识库」开关 | **没有开关**：自动识别，检测到 bz 并能力齐全就连上，逐项降级（录入按钮 / 笔记依据各管各的） | 用户判断不了「连上有什么好处、会多发什么出去」，一个勾选换不来信任 |
| §1.2 侧栏三档（这一屏 / 知识库 / 全书） | **只有全书**，没有档位；每次提问都以全书为依据 | 问的是「这本书讲了什么」，不是「这一屏讲了什么」 |
| §2-7 第一次提问弹「全书问答准备」 | **不弹窗**：建法与进度都在侧栏 AI 页签里，建好才出现输入框 | 弹窗只是把同一件事又说一遍 |
| §2-3 给 bz 加「嵌入能力」门面 | 保留，且**向量这一层整体归 bz**：模型的选型、维度、嵌入都由它给 | 两边各算各的向量，不在一个空间，检索会静默给错结果 |
| 设置里的「嵌入模型」 | **删掉**。bz 那边选什么模型，这边就用什么，只读显示 | 留一个能填错的框，就是留一条静默错误 |

由此产生的连带规则：

1. 已有画像里记的模型名与 bz 现在给的模型名对不上 → 判废，让用户重建（§2-10 的「不做迁移」照旧）；
2. 画像里**没记**模型名，而现在能取到模型名 → 同样判废（不认识来源的向量不能假装可比）；
3. bz 不在时**压缩方案仍可用**：它只吃对话模型，不碰向量库；
4. 没装 bz 时侧栏仍保留「观看视频教程」，那正是最需要的人。

## 一、需求

### 1. AI 知识库开关 + 两个录入按钮

设置面板增加「AI 知识库」开关（高级功能，默认关闭）。打开后，文字工具栏增加两颗按钮：

- **存为名词**
- **存为段落**

点击时调用 bz 插件知识盒里对应的两个入口，打开它的录入界面，并预填：选中文字、书名、章节、原文定位。

### 2. 侧栏 AI 三档

侧栏 AI 对话下方增加单选项（互斥，三选一）：

- **当前这一屏**（默认）
- **连接 AI 知识库**：回答走 bz 的第二大脑（检索用户的笔记库）
- **全书**：把这本书本身变成可用的问答依据

选「全书」后，第一次提问时弹界面，让用户手动选择下面两种方案之一，确认后才开始跑。

## 三、用户可感知的行为

### 3.1 开关与按钮

- 开关关闭时：文字工具栏维持现状（5 颗），任何入口都不出现这两颗按钮。
- 开关打开后：桌面 7 颗；手机仍在「⋯」里。
- 点「存为名词 / 存为段落」→ 弹出 bz 的知识盒录入界面，内容已预填。
- 保存成功 → 书里出现一条划线与双链想法 → 提示「已存为知识盒名词 / 段落」。
- bz 未装、未启用、版本旧 → 一句人话提示，指向安装 / 启用 / 更新 bz，不报错。
- bz 没配文献文件夹 → 提示里带一句「bz 里需要先配好文献文件夹」。

### 3.2 三档问答

未解锁时三档与开关同款处理：整组灰掉，点一下弹解锁说明（不要做成点了没反应的死按钮）。

- **当前这一屏**：与现在完全一致。
- **连接 AI 知识库**：提问时先检索第二大脑，回答依据里带笔记来源；索引没建或 bz 不可用时，用一句人话提示并临时退回「当前这一屏」。
- **全书**：
  - 没建画像 → 弹准备界面；
  - 已建 → 按选定的方案（向量检索 / 全书摘要）作答，并带当前这一屏；
  - 问答来源可点，点了打开对应笔记或书。

### 3.3 建画像

准备界面必须包含：

- 两种方案的对比（做法 / 好处 / 代价 / 适合什么问题）；
- 预估：「共 N 块，约 N 次嵌入请求」或「共 N 块，约 N+1 次 AI 请求」；
- 「开始」与「取消」。

进行中显示：第 i / N 块、当前阶段、可用于暂停 / 继续 / 取消；关闭弹层等于暂停，不丢进度。

完成后显示：块数、耗时、失败块数、所用模型；可「开始提问」「存为笔记」「重建」。

## 四、两种全书方案（界面要逐字说清的内容）

**A. 向量化检索**

- 做法：把全书按块转成向量存起来；提问时检索最相关的几块。
- 好处：便宜（只花嵌入的钱，不吃对话额度）、快、回答能指到具体章节。
- 代价：只看得到检索到的碎片，「全书脉络」这类问题容易答偏；需要 bz 的嵌入服务开着。
- 适合：「这个概念书里哪里讲过」「这句话什么意思」。

**B. AI 信息压缩**

- 做法：把全书分块逐块发给 AI 压成摘要；提问时带上整份摘要。
- 好处：有全局视角，能回答「这本书讲了什么」「作者的核心观点」。
- 代价：要发很多次大模型请求（按用户自己的 Key 计费）、慢、细节会被压掉。
- 适合：「帮我梳理全书」「讲了什么」这种总览。

## 八、检索层修订（2026-11-16）：从纯向量改成两路融合

§2 定的「全书依据 = 向量检索最相关的几块」执行了两周，真机暴露一个具体问题：
问「方鸿渐回国坐的船叫什么名字」，取前六块全是「方鸿渐」出现最多的日常段落，
真正写着船名的开头余弦只有 0.428，排不进前六，模型只能答「书里没有提到」。

这不是嵌入模型不行，是余弦只认「整体像不像」，不认「这个词在不在」。
修法不是换模型，是补一条字面通道。

### 8.1 与社区实现的对照（源码级）

| 项目 | 拿来的做法 | 落到 bz 的哪一处 |
|---|---|---|
| Copilot for Obsidian `src/search/v3` | 中文按**二字组**切词；BM25+（k1 1.2 / b 0.75 / δ 0.5）；字段权重 title 5 / heading 2.5 / body 1；`adaptiveCutoff`（floor 3 / ceiling 30 / 相对 0.3 / 按组去重） | `data/text-terms`、`data/bm25`、`data/hybrid-rank` |
| Anthropic Contextual Retrieval | 向量与 BM25 混合；两路分数不可比，按**名次**融合 | `data/hybrid-rank` 的 RRF（k = 60） |
| PageIndex | 章级摘要当「地图」，检索先选章再读整章 | 暂未落地（见 8.4） |
| Smart Composer | 分块 1000 字、top 10、`minSimilarity` 默认 0 | 与 bz 现有画像口径一致，不改 |
| Smart Connections | 块级向量 + 最近邻 | 核心已移到 `smart-env` 包，仓库里没有可分块细节可抄 |

### 8.2 落地了什么

1. **字面通道**（`data/block-retrieval`）：查询切词后走 BM25，章名单独一个字段
   且权重 2.5；**至少命中两个查询词**，或引号里的原话一字不差，才算候选。
   —— 中文里任意两个二字组都能撞上，只命中一个的块遍地都是。
2. **名次融合**（`data/hybrid-rank`）：向量与字面各自排序，用 RRF 合成一份。
   不归一化分数，因为余弦 0–1 与 BM25 的对数分不在一个量纲上。
3. **自适应收口**：保底 3 块、按章去重（六块依据不会全落在同一章）、
   上限仍是六块（`PORTRAIT_PICK_LIMIT`，本地模型 8k 窗口的预算）。
4. **邻居扩展**：前三条候选的同一章前后块以 0.85 倍分进候选池，和别的候选
   一起竞争名额——不额外占预算，跨块的论证能接上。
5. **章首补偿保留**：命中的章仍带回它自己的第一块（定义句多半在开头）。
6. **引文校验**（`data/ai-quote`）：prompt 要求引原文时用「」括起并注明章节；
   答案回来后把引文回**这次真正发出去的依据**里核，二字组覆盖率 < 80% 判为
   核不上，气泡下面加一行告警。不额外发请求。

### 8.3 没改的边界

- 依据预算仍是 8000 字、六块（`AI_EVIDENCE_LIMIT` / `PORTRAIT_PICK_LIMIT`）；
- 向量仍由 bz 算，模型名对不上仍判废；
- 压缩方案不参与混合检索（它没有向量，也没有原文块）；
- 跨书检索（书架「按意思搜」）同批换成混合，仍按书限量、总量封顶。

### 8.4 还没做

1 → 已于 §9.2 落地（流式输出）。
3 → 已于 §9.1 落地（章级地图 + 整章读）。
2 仍未做：**剧透门**（按 `reading.position` 截断可检索范围，默认「读到哪答到哪」）。
   设计要点先记在这里：截断点要用 `bookMap` 里当前章的**下标**，不要用字数百分比；
   当前章在目录里找不到时**不截**（宁可多答，也不能因为章名对不上而一个字都搜不到）；
   做成设置项、默认关——非虚构读者需要整本可查，小说读者才需要这道门。

## 九、读者路径补完（2026-11-16 晚）：章级地图、流式、追问检索

§8 解决的是「定位型」问题（某个词、某个专名在哪一段）。这一轮解决另外两类：

- **结构型**（这本书讲了什么、第九章写了什么、立场怎么变）——向量 top-k 天然做不到；
- **过程体验**（等 77 秒空白）与**理解型追问**（后来呢、和前文矛盾吗）。

### 9.1 章级地图 + 整章读（`data/book-map`）

对照实现：PageIndex 的 tree index（模型在树里做选择）、MindMax 的 chapter map
（能读完就整篇读）、BookRAG 的 BookIndex（树 + 查询分类）。

bz 不另建索引——画像里每一块都带 `chapter` 与 `text`，按章归组就是目录。

| 环节 | bz 的做法 | 与社区的区别 |
|---|---|---|
| 建图 | 一章一行：章名 + 一行说明（`guides` 的导读第一句 > 该章开头的第一句） | 同 |
| 补名 | 目录只有「第 7 节」时，从正文第一行取真名（`第九章贝尔格莱德Ⅰ：蓝色火车`） | 社区没这个问题（它们有真 EPUB nav）；bz 得自己补，否则「第九章」在目录里根本不存在 |
| 选章 | 字面打分（章名权重 3、说明权重 1），**不发模型调用** | PageIndex 让模型在树里做选择；本地 14B 单问 77 秒，为选章再加一次往返用户等不起 |
| 序号 | 问题点名第几章时，序号是**硬条件** | 二字组会把「第二十九章」切成「第二」，正好撞上「第二章」 |
| 读 | `chapterText` 按块顺序整章拼，超预算截断留痕 | 同 |
| 兜底 | 一章都挑不中：全书问题给「每章开头各一段」（`bookSpread`），其它问题给目录 + 检索结果 | MindMax「读不完按目录选」的同一取舍 |

**为什么全书问题不能只给目录**：目录那一行是句式（「当鸟群飞过阴霾的天际」），
答不出「在讲什么」。而检索永远向最像的几处收敛，全书问题要的恰恰是不收敛——
所以 `bookSpread` 均匀撒满每一章的开头。

**prompt 口径**：依据里带【全书目录】时补一句「没读到的章说『这一章本次没有展开』，
不要说『书里没有』」。不分开说，模型会拿目录之外的印象补一段，读者看不出哪句是猜的。

### 9.2 流式输出（`data/ai-sse` + `data/ai` + `shell/actions`）

| 环节 | 做法 |
|---|---|
| 切帧 | `drainSse`：`

` 先归一、多行 `data:`、`[DONE]`、心跳、只带 role 的空帧；坏 JSON 只丢那一帧，不炸整条回答 |
| 解码 | `TextDecoder(stream: true)`：一帧切在汉字三字节中间时，逐帧 `toString` 会解成乱码 |
| 超时 | 改成「两次收到字节之间的最长间隔」，每来一块就重排。**不能按「到字」计时**——DeepSeek 先连发 45 帧 `reasoning_content`，正文一个字都还没有 |
| 兼容 | 上游忽略 `stream` 回了整份 JSON（content-type 是 json）→ 退回一次性解析，不让整次提问失败 |
| 重绘 | 第一个字到了才把等待气泡换成回答气泡，之后**只改那一行 DOM**（80ms 节流）；收尾重绘一次，Markdown 与来源由那一次统一渲染 |
| 失败 | 已流出一半时保留收到的那部分，原因接在后面——抹掉半条答案等于用户白等半分钟 |

开流是**可选**的：`onDelta` 给了才开。识别扫描页、补元数据这类短任务不流式，
多一层状态只会多一个出错的地方。

真机（DeepSeek 官方端点）：首字 1039ms、3 帧、拼回文本与返回值一致。

### 9.3 追问补一次书内检索

追问原来只带眼前那一段（2000 字）+ 历史。问「他后来为什么变了」「这个说法和
前文矛盾吗」，答案往往在别处——模型看不到就只能猜。

- 查询 = 划线原文前 120 字 + 这一问（只拿问题算向量，「他」没有指代对象）；
- 取 3 块、1200 字封顶，作为 `【同书其他段落】` 单独一段进 system，与 `【原文】` 分开；
- system 补一句：别处的说法不要安到这段原文上；
- 任何一步失败返回空串，不拦这一问——追问的主依据始终是眼前这段。

### 9.4 边界

- 依据预算仍是 8000 字；整章读时目录与正文按 3:7 分，一章至少 600 字；
- 选章不发模型调用：字面打分错了（挑错章）比多花一次请求更常见，所以序号硬匹配
  优先级最高，挑不中就不挑；
- 剧透门仍未做（见 §8.4）。
