# AI 知识库与全书画像 · 决策记录

> 2026-11-07 定稿。这份文档只记录**已确认的决策**与**边界**，不规定实现方式；
> 具体技术方案由实现者决定，但不得违背下面的条目。

---

## 一、需求

### 1. AI 知识库开关 + 两个录入按钮

设置面板增加「AI 知识库」开关（高级功能，默认关闭）。打开后，文字工具栏增加两颗按钮：

- **存为名词**
- **存为段落**

点击时调用 bz 插件知识盒里对应的两个入口，打开它的录入界面，并预填：选中文字、书名、章节、原文定位。

### 2. 侧栏 AI 三档

侧栏 AI 对话下方增加单选项（互斥，三选一）：

- **当前这一屏**（默认）
- **连接 AI 知识库**：回答走 bz 的第二大脑（检索用户的笔记库）
- **全书**：把这本书本身变成可用的问答依据

选「全书」后，第一次提问时弹界面，让用户手动选择下面两种方案之一，确认后才开始跑。

## 二、已确认的决策

| # | 决策 |
|---|---|
| 1 | 全书**两种方案都做**，由用户在界面上二选一 |
| 2 | 方案对比必须**明明白白写清区别、好处、代价**（条目见第四节） |
| 3 | 允许修改 bz 仓库，为它增加两个对外入口：笔记库检索、嵌入能力。只加薄门面，**不改 bz 自己的索引器与向量库结构** |
| 4 | 全书画像（摘要或向量）**跟库走、单独存一个文件**；不进 bz-reader 的主数据文件，也不塞进 bz 的向量库 |
| 5 | 切块**按字数**，章节只当边界参考（建议 8000 字一块，实现时可微调） |
| 6 | 三档互斥，且**记住上次选择** |
| 7 | 「全书」必须**用户手动触发**：弹界面 → 看预估 → 点开始才跑；取消则退回「当前这一屏」并提示 |
| 8 | 全书档问答时**仍带当前这一屏**的正文 |
| 9 | **手机端不建画像**：手机只提示「请在电脑上建」，建好的可以直接用 |
| 10 | 换版本 = 另一本书：不做迁移、不做自动清理；另留一个「清理无主画像」的小出口 |
| 11 | 开关放在「AI 助手」组里；未激活整行灰掉 + 点击弹解锁；**不新增能力位**，复用现有的 AI 高级判定 |
| 12 | 两颗新按钮：**桌面摊开**成 7 颗，**手机收进「⋯」** |
| 13 | 第一次使用知识库 / 全书时，弹一次数据说明（会把什么发给 AI 接口），确认后不再弹 |
| 14 | 建画像过程中支持暂停 / 继续 / 取消；中断后可续跑 |
| 15 | 失败重试**只重跑失败块**，不整本重来（整本重来由用户主动点「重建」） |
| 16 | 存为名词 / 段落后自动回写：在原文处落一条划线，想法里写指向新笔记的双链 |
| 17 | 参考来源可点：知识库与全书问答的来源列表，点一条能打开对应笔记 |
| 18 | 书籍详情显示「全书画像：已建 / 未建」，并给一键入口 |
| 19 | 全书鸟瞰在有压缩画像时，显示每章的一句话摘要 |
| 20 | 画像完成后可以「存为笔记」（可选按钮，默认不自动落笔记） |

## 三、用户可感知的行为

### 3.1 开关与按钮

- 开关关闭时：文字工具栏维持现状（5 颗），任何入口都不出现这两颗按钮。
- 开关打开后：桌面 7 颗；手机仍在「⋯」里。
- 点「存为名词 / 存为段落」→ 弹出 bz 的知识盒录入界面，内容已预填。
- 保存成功 → 书里出现一条划线与双链想法 → 提示「已存为知识盒名词 / 段落」。
- bz 未装、未启用、版本旧 → 一句人话提示，指向安装 / 启用 / 更新 bz，不报错。
- bz 没配文献文件夹 → 提示里带一句「bz 里需要先配好文献文件夹」。

### 3.2 三档问答

未解锁时三档与开关同款处理：整组灰掉，点一下弹解锁说明（不要做成点了没反应的死按钮）。

- **当前这一屏**：与现在完全一致。
- **连接 AI 知识库**：提问时先检索第二大脑，回答依据里带笔记来源；索引没建或 bz 不可用时，用一句人话提示并临时退回「当前这一屏」。
- **全书**：
  - 没建画像 → 弹准备界面；
  - 已建 → 按选定的方案（向量检索 / 全书摘要）作答，并带当前这一屏；
  - 问答来源可点，点了打开对应笔记或书。

### 3.3 建画像

准备界面必须包含：

- 两种方案的对比（做法 / 好处 / 代价 / 适合什么问题）；
- 预估：「共 N 块，约 N 次嵌入请求」或「共 N 块，约 N+1 次 AI 请求」；
- 「开始」与「取消」。

进行中显示：第 i / N 块、当前阶段、可用于暂停 / 继续 / 取消；关闭弹层等于暂停，不丢进度。

完成后显示：块数、耗时、失败块数、所用模型；可「开始提问」「存为笔记」「重建」。

## 四、两种全书方案（界面要逐字说清的内容）

**A. 向量化检索**

- 做法：把全书按块转成向量存起来；提问时检索最相关的几块。
- 好处：便宜（只花嵌入的钱，不吃对话额度）、快、回答能指到具体章节。
- 代价：只看得到检索到的碎片，「全书脉络」这类问题容易答偏；需要 bz 的嵌入服务开着。
- 适合：「这个概念书里哪里讲过」「这句话什么意思」。

**B. AI 信息压缩**

- 做法：把全书分块逐块发给 AI 压成摘要；提问时带上整份摘要。
- 好处：有全局视角，能回答「这本书讲了什么」「作者的核心观点」。
- 代价：要发很多次大模型请求（按用户自己的 Key 计费）、慢、细节会被压掉。
- 适合：「帮我梳理全书」「讲了什么」这种总览。

---

## 五、明确不做

- 增量压缩、自动压缩（任何未经用户点击就调用 AI 的路径都不允许）
- 自动「先跑第一章试水」
- 换版本时迁移 / 自动清理旧画像
- 手机端建画像
- 新增能力位
- 把书的分块塞进 bz 的第二大脑向量库

---

## 六、跨仓库约定

- **bz 先发版**：新增「笔记库检索」与「嵌入能力」两个对外入口；bz 阅读探测不到就降级，不硬要求同时升级。
- bz 的改动只加门面，不碰它自己的索引器、向量库结构、面板与命令。
- 两个仓库都按各自的规矩走（测试先行、三道门、真机冒烟）。

---

## 七、一句话交接

先做「开关 + 两颗按钮」（可独立上线），再做「三档 + 知识库」，最后做「全书两种方案」。任何不确定的实现选择，回到这份文档里的决策与「明确不做」两条上判断。
