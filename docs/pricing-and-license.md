# 付费模式与上架方案（bz 阅读）

> 结论先行：
> 1. **离线激活码做不出「5 台设备上限」**。上限是记账问题，不是加密问题——要真做，必须有 5 个接口的在线服务。
> 2. **能上 Obsidian 商城**，但当前仓库过不了审核：缺 LICENSE、README 无付费/网络披露、base/pro 双包模式在商城分发下直接失效。
> 3. 推荐路径：**纯离线开卖验证 → 加在线名额 → 再上架**。别在没人买的时候先建服务器。

---

## 一、先认两件事

**① 激活码是一串字符串，天生可复制。**
现在的 `BZR1.<payload>.<sig>` 用 ECDSA P-256 离线验签，能证明「这串字是我签的」，但**不能证明「这台机器被允许用」**。同一个码粘到 100 台机器上，100 台都会验签通过。所以「默认 5 台」不是一个加密参数，是一张需要被查询和写入的表。

**② Obsidian 政策禁止混淆代码。**
所以任何设备锁都能被删几行 JS 绕过。目标不是「不可破解」，而是「**让正版用户 30 秒内能用上，让白嫖用户觉得麻烦到不如买**」。强 DRM 只会伤害付费用户（换机、离线、多端），且违反上架政策。

---

## 二、产品分层

三档。免费层必须能「完整读完一本书」，否则装完就卸载，试用都到不了。

| 能力 | 免费 | 试用 7 天 | 付费 |
|---|:--:|:--:|:--:|
| 打开 EPUB/TXT、目录、翻页、排版、主题、进度、本章搜索 | ✅ 永久 | ✅ | ✅ |
| 书签、划线想法、全书/跨书搜索、统计、AI 摘要、朗读、并排、BookMap、多格式 | ❌ 上锁 | ✅ | ✅ |
| 设备数 | — | 1 | 5（可释放） |
| 时长 | — | 7 个活跃日 | 买断当前大版本 |

**AI 必须走 BYO Key**（用户在设置页填自己的 baseUrl/Key）。理由：你不承担 token 成本；且一旦你代付，插件就「连接了付费服务」，商城分类和披露要求都会变复杂。

## 三、试用期设计

### 3.1 计时口径：累计活跃日，不是自然日

存 `trialDays: ["2026-11-03", "2026-11-05", ...]`，某天有打开阅读/书房即记一天。7 天 = 7 个不同日期。

自然日计时会因为出差、周末白白烧掉两天，用户体感极差；活跃日更公平，也更能反映「他到底试没试」。

### 3.2 防改时钟（轻量，不激进）

```ts
// storage 里维护 lastSeenTs（历史最大时间戳）
if (now < lastSeenTs - 12h) clockAnomaly++;   // 可能只是调了时区，不立刻封
lastSeenTs = max(lastSeenTs, now);
// 累计 3 次，或回拨超过 7 天 → 试用作废
```

规则必须写在设置页可见处，避免误伤后无法解释。这是「防懒人」不是「防破解」。

### 3.3 到期后的降级行为（这条最重要）

到期后：

- 高级入口**保留在原来的位置**，点开显示「试用已结束」卡片（含二维码 / 群号 / 购买链接）
- **数据一律不锁、可导出**：划线、书签、统计永远能看、能导出
- 绝不出现「不付费打不开自己的笔记」——这是差评第一来源，也违背 Obsidian 的数据自主原则

### 3.4 试用怎么发放（两条路线）

| | A. 装完直接给 7 天 | B. 加群领码才给 7 天 |
|---|---|---|
| 转化率 | 高（先体验后付费） | 低一半以上（门槛在体验之前） |
| 拿到用户线索 | 无 | 有（QQ 群） |
| 反滥用 | 每机一次（本地判定） | 必须服务端核销，否则码 1 小时传遍全网 |

**推荐 A+B 叠加**：装完自动 7 天；群里发「续 7 天码 / 立减券」，把群当留存池而不是闸门。

如果坚持「加群才给试用」，那试用码必须是**一次性核销码**：

```
payload = { v:2, id:"TRIAL-0001", plan:"trial", exp:+7d, once:true }
```
服务端记录 `codeId → 首个 installId`，之后任何其他 installId 兑换一律拒绝；同一 installId 终身只能核销一次试用码。

## 四、激活码格式（升级到 BZR2）

保持离线可验签（断网也能确认码是真的），但把「记账信息」放进 payload：

```json
{
  "v": 2,
  "id": "BZR-2026-0001",
  "name": "张三",
  "plan": "lifetime",          // lifetime | year | trial
  "exp": 0,                     // 0/缺省 = 永久
  "maxDevices": 5
}
```

- `id` 是订单号/码号，**服务端拿它记账**
- v1 老码兼容：无 `id` 视为不限额，已发出去的码不作废
- 真正决定「能不能用」的是**设备凭据（device token）**，不是这串码本身

## 五、设备绑定

### 5.1 不要采硬件指纹

政策敏感、隐私争议、用户反感（"一个阅读器凭什么读我硬盘序列号"）。改用插件自己生成的随机 `installId`（UUID），显示在设置页，用户可复制、可发给客服。

### 5.2 一个必须避开的坑：installId 不能存在插件目录

现在数据落 `<插件目录>/storage/bz-reader.json`，而 Obsidian 的插件目录是 **per-vault** 的。同一台电脑开两个 vault，就是两个 installId，吃掉两个名额。

**installId 要存 Obsidian 的全局本地存储**：

```ts
const APP = (this.app as any);
let id = APP.loadLocalStorage('bz-reader-install-id');
if (!id) { id = crypto.randomUUID(); APP.saveLocalStorage('bz-reader-install-id', id); }
```

### 5.3 激活流程

```
输入激活码
  → 本地验签（秒回，离线也行）
  → 首次需联网 POST /v1/activate { code, installId, pluginVersion }
       ├─ 名额未满 → 返回 token（服务端私钥签，含 codeId/installId/exp）
       └─ 已满 5   → 409 + 设备列表（installId 前 8 位、首激活时间、最后活跃）
                     提示「去旧设备释放，或点这里远程释放」
  → token 缓存到 storage，之后 30 天免联网
  → 超过 30 天未联网：提示一次「连下网」，再给 7 天软宽限（共 37 天）才降级
```

### 5.4 释放设备是必须功能

设置页要有「我的设备」列表，支持「释放本机」和「远程踢掉某台」。否则用户换机就被卡死，会直接骂人——这是付费插件最常见的差评源。

### 5.5 5 台够不够

桌面 2 + 手机 1 + 平板 1 + 备用 1。够。真不够就加一档「支持者版 10 台」。

## 六、在线服务（最小可用）

一张表 + 四个接口，不要更多。

```
POST /v1/activate  { code, installId, version }  → { token, devices[] } | 409
POST /v1/refresh   { token }                     → { token }      // 心跳 + 续期
POST /v1/release   { token, targetInstallId }    → { ok }
POST /v1/redeem    { code, installId }           → 一次性试用码核销
```

**存储两张表**：

- `codes(codeId PK, plan, exp, maxDevices, note, createdAt)`
- `devices(codeId, installId, firstAt, lastAt, version)` 主键 `(codeId, installId)`

**红线**：激活请求里只能有 `code + installId + version + 时间`。**绝对不能夹带任何使用行为数据**——Obsidian 政策禁止 client-side telemetry，审核会看。

**必须用 `requestUrl`**，不用 `fetch`（CORS + 审核偏好）。

### 选型与成本

| 方案 | 成本 | 国内访问 |
|---|---|---|
| Cloudflare Workers + D1 | ¥0（免费额度 10 万请求/天，够几千用户） | workers.dev 不稳，需绑自定义域名 |
| 腾讯云 SCF + 云开发 | ~¥30/月 | 快，但域名需备案 |
| 一台轻量服务器 | ~¥60/月 | 快，需备案 |

早期足够用 CF。**域名解析到境外不需要备案**，但速度一般；若目标用户集中在国内且量大，再迁国内云。

## 七、收款与发码

### 早期（0～50 单）：最土的最省事

爱发电商品页（支持微信/支付宝）→ 订单通知手动发码。写成「付款后 24h 内发货，急单加群」。零开发成本，还能聊到第一批用户。

### 上量后：半自动

爱发电 webhook → 你的 Worker → 生成 BZR2 码 → 落库 → 返回兑换页/邮件。抽成 5%，可接受。

### 国际

Paddle / Lemon Squeezy：支持支付宝、自动发码、代缴税，抽成 ~5%+。懒人首选，但需要注意「数字商品」条款。

### 定价建议

| 档位 | 价格 | 说明 |
|---|---|---|
| 早鸟 | ¥29（限 100） | 制造紧迫感，也换早期口碑 |
| 标准 | ¥59 买断 | 国内工具类甜区；再高要显著更强的功能 |
| 支持者 | ¥129 | 10 台设备 + 名字进 README，毛利最高 |

**不做订阅**。Obsidian 用户对订阅极度反感，且你没有持续服务成本（AI 是用户自己的 key）。

## 八、能上 Obsidian 商城吗

**能。付费插件是官方允许的。** 但有 5 个硬门槛。

### 8.1 政策依据（2025 年新审核体系）

| 政策 | 原文要点 |
|---|---|
| 付费允许 | Community 不是商店，不提供支付；开发者可用外部 license key / API key / login gate |
| 必须标注 | 分三类：Free / Optional payments / **Paid**（"必须付费才能用主要功能，即使提供试用"）→ 我们属于 Paid |
| 必须披露 | README 明确写「完整功能需付费」 |
| 网络使用 | README 写清：哪个服务、为什么需要、发什么数据 |
| 禁止混淆 | 代码必须可读，不得加密/混淆 main.js |
| 禁止遥测 | 不得包含 client-side telemetry |
| 禁止自更新 | 不得自行下载更新 |
| 必须开源（新插件） | "For now, we are not accepting new closed source plugins into the directory" |
| LICENSE | 必须有 LICENSE 文件并声明许可证 |

审核团队成员在论坛明确答复过：**只要 README 披露，付费门 + 外链购买是可以的**；Obsidian 不提供内购方案，支付方式自负。

### 8.2 当前仓库的差距

| 项 | 状态 | 要做 |
|---|---|---|
| LICENSE 文件 | ❌ 缺（`package.json` 写了 MIT 但没文件） | 补 `LICENSE`，版权行写清年份与署名 |
| README 付费披露 | ❌ 无 | 加「付费说明」段：试用 7 天、价格、购买、激活方式 |
| README 网络披露 | ❌ 无 | 写清激活服务域名、发送字段、为什么、隐私承诺 |
| README 语言 | ⚠️ 全中文 | 补英文段（审核者是英文母语） |
| **base/pro 双包** | ⚠️ 致命 | 商城只分发**单个 main.js**，双包「覆盖安装」模式上架即失效。必须改**单包 + 运行时 gate** |
| 激活逻辑开源 | ⚠️ 需确认 | 公钥公开无妨，但要确保没有把「试用判定」写成看不懂的加密逻辑 |
| `requestUrl` | ⚠️ 待改 | 全都用 Obsidian 的 `requestUrl` |
| manifest | ⚠️ 中文化 | description 建议英文；`minAppVersion` 与 `versions.json` 对齐 |
| 自动审核 | ⚠️ 未跑 | 用官方 eslint 插件本地自检 + developer dashboard 预览扫描（每版本都扫，失败 24h 下架） |
| 移动端 | ⚠️ 风险 | iOS 上显示「去网站购买」有 App Store 规则风险。建议移动端只显示「已购买请激活」，不放购买按钮 |

### 8.3 双包改造（上架前必做）

现在的 `src/entry/base.ts` / `pro.ts` 产出两个 bundle，用户覆盖安装。商城只认一个包，这条路会被堵死。

改法（也是你之前定的方向）：

- 只构建 **pro 单包**
- 用运行时 gate 控制能力：`capabilities = licensed ? ALL : FREE`
- 免费功能照常，高级入口显示锁标 + 点击开「解锁」弹层
- 好处：不用维护两套产物；坏处：免费用户也会下载到 pro 代码（体积多几百 KB，无实际损失）

`esbuild.config.mjs` 的 `--target base|pro` 保留做本地对照，但发版只出 pro。

### 8.4 提交路径

1. 仓库公开（GitHub）
2. 补 LICENSE / README / manifest
3. 建 `versions.json`（version → minAppVersion）
4. 打 GitHub Release（附 `main.js`、`manifest.json`、`styles.css`）
5. PR 到 `obsidianmd/obsidian-releases`，在 `community-plugins.json` 加一行
6. 审核通过后用 developer dashboard 管后续版本

周期通常几天到几周。国内用户从商城安装/更新走 GitHub，网络不稳，这点要在群里提前说明（给手动下载兜底）。

| 阶段 | 做什么 | 门槛 | 上线成本 |
|---|---|---|---|

## 十、风险清单

1. **私钥泄露 = 所有码作废重签**。`scripts/keys/private.pem` 已在 `.gitignore`，务必离线备份到密码管理器；建议一年内上 HSM 或至少加密存放。
2. **开源 = 验签逻辑公开**。这没问题（安全靠私钥不靠藏代码），但别把「试用计时」写成可笑的谜题式混淆——违反政策且没意义。
3. **一定会被盗版**。接受它。对策是更新频率 + 群服务 + 价格合理，不是加壳。
4. **移动端合规**：iOS 站外支付风险独立于 Obsidian 政策，自行评估。
5. **隐私红线**：激活接口只收 `code + installId + version`。加一个字段都要重新想清楚——client telemetry 是被明确禁止的。

## 十一、附录：不做「5 台上限」时，怎么防泄露

### 11.1 先分清泄露的是什么

| 泄露对象 | 后果 | 能不能撤销 |
|---|---|---|
| **激活码** | 别人能解锁 | 能（码可轮换、可吊销） |
| **更新通道** | 别人能持续拿新版 | 能（踢权限，最干净） |
| **云端能力** | 别人能免费用你的服务 | 能（断开账号） |

三者可以分开设防。**码是最不值钱的资产**——它本来就该是可轮换、可作废的。真正的护城河是后两者。

所以「码泄露 = 无限解锁」只在三个条件**同时**成立时：永久码 + 无吊销 + 无版本约束。打破任意一条就有上限。

### 11.2 五种手段对比

| # | 手段 | 做法 | 需联网 | 开发成本 | 伤正版吗 | 挡住谁 |
|---|---|---|---|---|---|---|
| 1 | **个性化水印** | payload 带购买者名/订单尾号，设置页与关于页显示「本副本授权给 XXX」 | 否 | 极低（字段已有，只差展示） | 不伤 | 公开发布的人（丢脸 + 可追溯） |
| 2 | **短期码 + 免费续期** | 码 90 天有效，到期前静默联网免费换新码，旧码同时作废 | 是（每季一次） | 低（1 个接口） | 很轻 | 泄露后长期白嫖 |
| 3 | **在线吊销名单** | 只维护 `revoked[]` 列表，客户端每周拉一次；发现码在闲鱼/GitHub 流传就加进去 | 是（周期） | 低 | 极低（7～14 天宽限） | 已确认泄露的码 |
| 4 | **私有更新通道** | 付费用户进私有 repo（BRAT 安装）或私有更新源，泄露 = 踢人 | 是 | **零**（用 GitHub 权限） | 中（要装 BRAT，国内门槛高） | 想持续用新版的人 |
| 5 | **云端能力** | 核心价值依赖你的服务（AI 代理、跨端进度同步、统计聚合） | 是 | 高 | 不伤 | 想用核心价值的人 |

### 11.3 三种推荐组合

**A. 纯离线，0 服务器**：只能做 1 + 4。
个性化水印 + 私有更新通道。老实说：**码本身防不住，别在它上面花钱**。真正的防线是「新版只有付费用户能拿到」。

**B. 轻服务端（推荐）**：1 + 2 + 3。
不做设备表，只做 `codes` 表 + `revoked` 字段 + 一个续期接口。平时运维量为 0，发现泄露才动手。这比设备上限简单得多，也不伤害多设备用户。

**C. 服务化（最彻底）**：5 为主。
代码全开源也不怕——没有账号就用不了云端能力。适用于「卖服务而不是卖开关」，但对纯本地阅读器来说，云端价值偏弱，不建议作为主线。

### 11.4 为什么「短期码」比「设备上限」更划算

| | 设备上限 | 短期码 |
|---|---|---|
| 服务端维护 | devices 表 + 名额争抢 | codes 表 + 一个 revoke 字段 |
| 典型客诉 | 换机被卡、重装被卡、多 vault 吃名额、要求远程释放 | 几乎无（静默续期） |
| 误伤正版 | 高 | 低 |
| 对泄露的效果 | 直接阻断 | 90 天后自然死亡 |
| 用户感知 | 「你在监视我」 | 无感 |

设备上限是在**事前**堵人，短期码是让泄露的码**自然过期**。后者的实现成本和客诉都低一个量级。

### 11.5 被低估的杠杆：版本迭代

泄露出去的 `main.js` 是一份**冻结的快照**。只要新版持续带来用户想要的东西（新格式、新功能、数据 schema 升级、bug 修复），盗版用户就会被永久甩在后面。

把更新节奏当防线，比把代码锁死有效得多——而且免费。

> 具体做法：数据 schema 升级时做一次性迁移（新字段不向后兼容），旧版读到新数据会报「请升级到最新版」。这不是恶意，是正常工程行为，但客观上让旧快照失去价值。

### 11.6 底线（要对齐预期）

- 政策禁止混淆代码，所以「删几行绕过」永远存在。任何方案都只是**提高门槛**。
- 目标定成：让 95% 的人觉得「不如去买」，接受 5% 白嫖。
- **为 5% 的白嫖增加 95% 正版用户的摩擦，是亏本买卖。** 这是所有付费插件最常见的战略错误。

## 十二、竞品调研：Obsidian 付费插件实际怎么做的

> 调研时间 2026-11，来源为插件目录详情页与官方定价页。

### 12.1 四种打法

| 打法 | 代表 | 价格 | 授权机制 | 联网 |
|---|---|---|---|---|
| **服务化订阅** | Copilot for Obsidian | $7.99 / $14.99 月，$349.99 买断 | 账号 + 服务端额度 | 强依赖 |
| **一次性买断 + 离线签名** | Bases Power Pack / Prose Lens | $29 / $12 一次性 | Ed25519 离线验签，公钥内嵌 | **完全不联网** |
| **设备指纹激活** | jinianri（国产） | ¥29.9 永久 + 48h 试用 | 设备指纹 → 人工发码 | 否（指纹手动报） |
| **闭源自建分发** | Cornell Notes | $14 一次性 | 自建更新后端 + Paddle | 是（拉更新） |

### 12.2 逐家细节

**Copilot for Obsidian（Brevilabs）** — 品类第一，最有参考价值
- 开源 AGPL-3.0，**同一个安装包，免费层和付费层是两个开关**
- 免费 = BYOK（用户自己填 key），功能几乎全给
- 付费 = **用作者的托管模型 + 额度**，不是锁功能
- 关键机制：**付费价值天然依赖服务端**，所以根本不需要设备锁——盗版插件没有他们的 API 额度也没用
- 真实数字：170 万下载 → 1,465 个订阅，**转化 0.09%**；MRR ≈ $1.98 万
- 启示：这是「卖服务不卖开关」唯一跑通的样本，但它有云端成本撑着，纯本地阅读器学不了

**Bases Power Pack** — 跟 bz-reader 最像
- $29 一次性，免费 Lite 层 + 付费 Premium
- Ed25519 离线验签（tweetnacl），**无账号、无服务器、无网络调用**
- 「enforced at render time, not just hidden in the UI」——校验在渲染路径上，不只是藏 UI
- 支付和发码**完全外包**给 Lemon Squeezy / Gumroad，代码里留 `TODO(billing)`，插件不用改
- 在目录里标 **Optional payments**

**Prose Lens** — 最激进，把「不追踪」写成卖点
- $12 一次性，Ed25519 离线验签
- 原文：「makes no network calls. Not for analysis, **not for licensing**, not for updates, not ever」
- 原文：「**One key covers all your devices. The license is not tied to a machine and has no activation limit** — buy once, use the same key everywhere, forever」
- 连更新都不走自己的通道（靠 GitHub Release），代码 MIT 开源
- 在目录里标 Optional payments

**jinianri（国产中文插件）** — 国内活样本
- ¥29.9 永久，**48 小时试用**（比 7 天短）
- 授权方式是**设备指纹**：用户复制指纹 → 小红书下单 → 作者回激活码
- 已上架官方目录，详情页直接写「付费 · 48 小时试用 · ¥29.9 永久激活」
- 启示：小体量个人开发者，人工发码完全够用；但设备指纹=换机必找作者，客诉结构被动

**SystemSculpt** — 订阅 + 买断并行
- $9/月 或 $149 终身，明确写 **5-device personal license**
- 但有账号、有 dashboard、有 credits —— 是服务型产品，5 台能真记账
- 启示：「5 台」这个数字在行业里是标准表述，但只有服务化产品才兜得住

**Cornell Notes** — 闭源的代价
- $14 一次性，Paddle 收款
- 作者自述：「**cannot be distributed via the official Obsidian community store (which requires open-source code)**」，所以被迫自建整套更新后端
- 自述扣掉 VAT、Paddle 抽成、汇率后剩约 70%，再付基础设施和 20-40% 所得税，实际到手约一半
- 启示：闭源不是不能卖，但失去商城流量 + 自建分发基建，成本是真实的

### 12.3 三个反常识的发现

**① 卖得好的本地工具，主动声明「不联网、不限设备」**
Prose Lens 把「无网络调用、无激活次数上限」印在商品页当卖点。付费用户买的不是「被允许使用」，是「不被打扰」。这跟直觉相反，但在隐私敏感的 Obsidian 社群里极其有效。

**② 做设备限制的，都是有云端用量的服务型产品**
Copilot 限的是**额度**不是设备；SystemSculpt 限 5 台但有账号体系。纯本地工具做设备锁的，只有 jinianri 这种小体量样本，且要人工发码兜着。

**③ 闭源 = 放弃商城流量**
Cornell Notes 是被迫自建分发。这条对 bz-reader 是明确的取舍：想上商城就必须开源。

### 12.4 对 bz-reader 的直接结论

**你现在的技术栈跟 Bases Power Pack 一模一样**：ECDSA（它用 Ed25519）离线验签 + 公钥内嵌 + 外部发码。它卖 $29、不限设备、Lemon Squeezy 交付、标 Optional payments、上了官方目录。

这条路已经被验证过，**不需要发明新机制**。差别只在：

| | Bases Power Pack | bz-reader 建议 |
|---|---|---|
| 价格 | $29（≈¥200） | ¥39～59（国内定价带） |
| 试用 | 无（免费 Lite 层替代） | 7 天全功能 |
| 设备 | 不限 | 不限（不做锁） |
| 支付 | Lemon Squeezy / Gumroad | 爱发电（国内）/ Paddle（国际） |
| 发码 | 自动（商店后台） | 早期人工，后期 webhook 自动 |

**转化率的现实预期**：Copilot 170 万下载换 1,465 订阅 = 0.09%。1 万下载大约 9 个付费，¥59 × 9 ≈ ¥531。这个数字决定了策略：**靠商城自然流量养不活，私域（QQ 群 / 小红书）才是主要成交场景**，商城的作用是「建立信任 + 被搜索到」，不是「卖货渠道」。

## 十三、基础版 / 高级版的功能切分

### 13.1 三条原则

**① 切「产出」，不切「依靠」。**
字号、目录、翻页、进度、脚注是「读书这件事本身」。切在这里，试用一结束产品就变砖，用户不会买，会卸。

**② 切「频率」，不切「深度」。**
统计每周看一次、导出读完一本用一次、AI 偶尔用一次——这些切掉不痛。划线和书签每读几页就用一次，切掉等于断手。

**③ 绝不限量。**
「免费版只能划 3 条线」是最招骂的切法：既显得小气，又制造「我的东西被扣住」的屈辱感。宁可整块不给，也不给半残。

### 13.2 切分表

| 功能 | 免费 | 高级 | 切在这里的理由 |
|---|:--:|:--:|---|
| EPUB / TXT 打开、书架、导入、封面 | ✅ | | 地基 |
| 目录（桌面左侧栏 / 移动抽屉）、章节跳转 | ✅ | | 地基 |
| 翻页、手势、键盘、滚轮、缩放 | ✅ | | 地基 |
| 排版（字号/行距/边距/字体/对齐） | ✅ | | 地基，切了就是坏产品 |
| 主题（跟随 Obsidian / 明亮）、全屏、进度、剩余时间 | ✅ | | 地基 |
| **脚注 / 尾注 / 书内锚点 / 外链** | ✅ | | 书的一部分，切了这本书就是残的 |
| **本章内 / 全书搜索**（单本书内） | ✅ | | 找一句话是本能的；只扫当前书，成本低 |
| **跨书搜索**（所有书里找） | ❌ | ✅ | 书多了才有价值，且要逐本开引擎扫 |
| **书签** | ✅ | | 「接着读」的组成部分 |
| **划线 4 色 + 想法** | ✅ | | **见 13.4，这是刻意免费** |
| 查看 / 复制自己的标注 | ✅ | | 数据自主，政策红线 |
| **标注导出 Markdown**（按章节组织 + frontmatter） | ❌ | ✅ | **第一付费点** |
| **书摘卡片**（canvas 分享图） | ❌ | ✅ | 产出物，社交货币 |
| **阅读统计**（总时长/热力图/每本进度） | ❌ | ✅ | 低频，但重度用户在意 |
| **AI 摘要 / 释 / 译**（BYO Key） | ❌ | ✅ | 增量价值 |
| **多格式**：mobi / azw3 / fb2 / cbz 漫画 | ❌ | ✅ | 见 13.5 |
| **竖排 / 双栏** | ❌ | ✅ | 小众排版偏好 |
| **朗读（TTS）** | ❌ | ✅ | 小众但刚需（通勤） |
| **并排 / 双语对照** | ❌ | ✅ | 学外语场景 |
| **BookMap / 章节缩览** | ❌ | ✅ | 锦上添花 |

### 13.3 搜索的分界线：一本书内 vs 跨书

- **书内搜索（本章 + 全书）免费**。用户想问的是「这句话在第几章」，这是阅读行为的一部分；只扫当前这一本书，成本可控。
- **跨书搜索收费**。用户想问的是「我在哪本书里读到过这句话」，只有书架几十本的人才会产生这个需求。

⚠️ 但有个隐患：现在的跨书搜索是**逐本开临时引擎扫、不建索引**，性能天然比书内慢一个量级。**收费的功能必须比免费的体验更好**——如果付费用户点了要转圈十几秒，这条会成为差评焦点。要做这个付费点，得先给它一个轻量索引，或者至少并发扫描 + 边扫边出 + 明确的进度反馈。

### 13.4 为什么划线必须免费（这是全文最重要的一个决定）

直觉上划线是「核心功能」，应该收费。但算一笔账：

- 划线是**付费动机的发动机**。用户划了 200 条，才会迫切想「导出成 Markdown 变成笔记」、才会想看「我这一年读了多少」、才会想「搜一下那句话在哪本书里」。
- 如果把划线锁住，用户在试用期内**攒不出存量**；到期后没有「沉没成本」，卸载毫无心理负担——他只是在试用一个阅读器。
- 反过来，划线免费 = 用户在你的插件里存了 200 条自己的思考。这时候「导出」「统计」「卡片」才变成「把我已经投入的东西取出来」，而不是「买一个新功能」。

这就是禀赋效应的用法：**先让用户拥有，再卖给他处置权。**

对照证据：Prose Lens 免费给全部 7 种标记，只把「重写工具」收费；Bases Power Pack 免费给第二大功能 Kanban。**主流做法都是把「记录」放开，把「加工」收费。**

而且划线免费不违反政策：数据永远可读可复制，只是导出成 Markdown 文件（带 frontmatter / 按章节组织 / 写进 vault）属于加工能力。

#### 导出的三级切分（避免变成「数据人质」）

划线免费、导出收费，这条组合成立的前提是：**用户自己的数据必须永远拿得走**。

| 能力 | 免费 | 付费 |
|---|:--:|:--:|
| 看、复制自己的划线（纯文本） | ✅ | |
| 复制单条划线 + 位置链接（单条，非批量） | ✅ | |
| **结构化导出**：按章节组织 + frontmatter + callout + 标签分组 | ❌ | ✅ |
| **活同步成书籍笔记**（持续追加，非一次性快照） | ❌ | ✅ |
| 书摘卡片（图片） | ❌ | ✅ |

原则：**免费给「能拿走」，付费给「拿得漂亮」**。付费卖的是整理好的形态，不是解押。

两个细节：

1. **到期后不能只给灰按钮**。点导出要给「你在这本书划了 47 条 → 预览前 3 条 → 解锁完整导出」，同时留一个不显眼的「复制纯文本」。只给锁是逼卸载，给预览是让人看见自己攒的东西值多少钱。
2. **单条复制建议留在免费**，哪怕双链整体是高级版。一次只能拿一条不构成搬家，但每粘一条到笔记里都是一次广告——别人看到那行可点击的链接，第一反应是问「这什么插件」。

⚠️ 另一面：导出是**一次性动作**，导完就不再需要。它是「入门级付费诱因」，不是「持续付费理由」。买断制没问题；若将来想转订阅，得靠「活同步」这种持续性的能力撑。

### 13.5 多格式怎么切

EPUB + TXT 免费，其余（mobi / azw3 / fb2 / cbz）收费。

注意两个坑：

1. **不能静默失败**。用户拖进一本 mobi，免费版必须明确提示「此格式需高级版」+ 试用 / 解锁入口，而不是打不开就没了。静默失败会被当成 bug，直接卸载。
2. **漫画 cbz 单独看**。它跟文字书的用户群不太重叠，如果做得好可以单独作为卖点，但别放进免费版稀释价值。

### 13.6 渐进式付费墙（别一上来全是锁）

试用到期后，**不要把所有高级入口变成灰色**。做成「先给看，后收钱」：

| 用户点了什么 | 显示什么 |
|---|---|
| 「导出」 | 「你在这本书划了 47 条，可以导出成 Markdown」+ 前 3 条预览 + 解锁按钮 |
| 「统计」 | 热力图正常渲染但模糊 + 「试用还剩 0 天」+ 解锁按钮 |
| 「AI 摘要」 | 显示一句示例结果 + 解锁按钮 |
| 高级格式的锁 | 直接给「试用 7 天」入口，不要只给购买 |

原则：**让他看见自己已经拥有的东西值多少钱，而不是告诉他少了什么。**

### 13.7 不建议切的清单（会直接导致差评）

| 别切 | 为什么 |
|---|---|
| 字号 / 主题 / 行距 | 试用后不能舒服读书 = 产品变砖 |
| 脚注 / 链接 | 书的一部分，切了等于给残本 |
| 目录 / 章节跳转 | 长书没法读 |
| 书签 | 「接着读」断掉 |
| 查看、复制自己的标注 | 政策要求数据可读；也是差评第一来源 |
| 书架容量 | 限书数是最招骂的切法之一 |
| 离线可用性 | 阅读器断网不能用 = 不可接受 |

### 13.8 一句话总结

> **免费版：读完一本书。付费版：把这本书变成你的资产。**
>
> 分界线画在「读完」和「变成资产」之间——不在「能不能读」和「读得舒服不舒服」之间。

### 15.2 点付费功能 → 功能对照表，不是价目表

`overlayUnlock()` 现在的结构：

1. 标题写着「用户刚想做的那件事」（如「把划线导出成结构化 Markdown」）；
2. 一张 14 行的基础版 / 高级版对照表（`PLAN_TABLE`）——哪项有、哪项没有，一眼看完；
3. 两个出口：**去购买**、**加交流群**；
4. 激活码输入框固定在弹层页脚，表格再长也不会被挤出视口。

表里每一项单独一行，不合并（用户明确要求）。`PLAN_TABLE` 改一行就能调，不用动渲染。

### 15.3 付费门控清单（这是本节的重点）

第一版只拦了导出 / 卡片 / 统计 / 跨书搜索 / AI / 多格式，**朗读、并排、竖排、BookMap 全都能白用**。现在补成一张表，凡是 `PLAN_TABLE` 里标了高级版的能力，都有一个入口被拦：

| 能力 | 入口 | 拦在哪 |
|---|---|---|
| export | 导出按钮 / 复制 Markdown | `actions` → `requireCap('export')` |
| card | 书摘卡片 / 年度海报 | `requireCap('card')` |
| stats | 书房统计页 | 整页锁态（模糊热力图 + 解锁按钮） |
| crossSearch | 搜索结果范围切「全库」 | `requireCap('crossSearch')` |
| ai | 划词 AI / 翻译、侧栏提问 | `requireCap('ai')` |
| fullFormats | 导入面板、**打开已存在的 mobi** | 导入按格式过滤；开书时再拦一次 |
| vertical | 排版面板与设置页的「竖排 / 双栏」 | `setPref` 里拦，**改回横排永远放行** |
| tts | 阅读栏朗读按钮、快捷键 `r` | `toggleTts` 里拦，**停止永远放行** |
| parallel | 阅读栏并排按钮 | `toggleParallel` 里拦，**关闭永远放行** |
| bookmap | 阅读栏 Book Map | `requireCap('bookmap')` |

三条规则写进了代码注释，避免以后又漏：

1. **关闭动作永远放行**——不能把人锁在竖排里、锁在朗读中；
2. **可见但点不开，好过直接消失**——书架仍然扫描全部格式，点了才提示；否则用户会以为书被插件删了；
3. **拦截要发生在「切换的那一下」**，不是在结果里悄悄少几本书。

### 15.4 数据目录：默认 `bz 阅读/`，可迁移

- 数据根从 `<插件目录>/storage/` 挪到**库根目录的 `bz 阅读/`**（`DEFAULT_DATA_DIR`）。理由：`.obsidian` 常被同步工具跳过，重装插件也容易连带清掉；用户看不见自己的书摘在哪，出事没法自救。
- 目录指针存 `localStorage`（`bzs-data-dir-v1`）——先有鸡还是先有蛋：不知道目录就读不到写着目录的那个文件。
- 老用户升级时**自动搬迁一次**：新目录没有 JSON 且老 `storage/` 有数据 → 复制过去（`migrate.ts`），失败不算错。
- 改目录必须**二次确认**：弹层摊开「从哪 → 到哪」，说明会搬什么；确认后走 `落盘 → 复制 → 校验 → 切指针 → 重新加载 → 删旧`。
- 任何一步失败都**保持原目录不动**。顺序不能反：先复制后删，用户几百条划线只有一份。

实测：把 `bz 阅读` 迁到 `bz 阅读归档`，6 个文件整树复制、旧目录随后删除、书架与标注无变化。
