## 9. 售卖商品后台字段对照

「设置 → 售卖商品 → 上架新商品」的表单：

| 字段 | 填什么 |
|---|---|
| 商品名称 | 第 1 节 |
| 型号（SKU）名称 | `永久授权`，只建一档 |
| 型号价格 | 第 3 节 |
| 商品介绍 / 详情 | 第 5 节 |
| 库存 | 不限 |
| 每人限购 | 1 |
| 提供商品的方式 | **添加作品集**（见下） |
| 物流 | 虚拟商品，不收集地址 |

**交付机制**：售卖商品靠「作品集」交付——买家付款后拿到的是作品集的查看权，不是文件。

1. 先建作品集，叫 `bz Reader 高级版 · 激活指南`；
2. 里面发一条动态（所有人可见）：激活步骤 + 「激活码在付款后的私信里」；
3. 商品型号的「选择提供商品的方式」→ 添加作品集 → 选它；
4. 买家付款后能看到教程，码由自动随机回复下发。

> 「卡密 / 自动发货 / 补货 API」是另一套玩法（服务端补货）。我们现在用「自动随机回复」够用：
> 每行一枚，发完为止，补货就是往框里加行。

## 11. 码池怎么管

| 想干的 | 能不能 | 怎么做 |
|---|---|---|
| 补货 | 能 | 随机回复框末尾追加新行，签新码，编号接着排 |
| 看还剩几枚 | 能 | 数框里剩下的行数（发一行消耗一行） |
| 停售 | 能 | 商品下架 |
| 让**已发出**的码失效 | **不能** | 见下 |

插件是离线验签，公钥里没有吊销入口。码发出去之后，只要没到期就一直有效。
`payload.id`（`BZR-AF-2026-0001` 这种）是给将来做吊销名单留的口子，**代码还没实现**。

唯一能真正作废的办法是换 `scripts/keys` 重签 + 更新内嵌公钥 + 发版，但那样
**所有已售码同时失效**，老用户会集体炸锅。不能当常规手段。

现实止损：

- 某枚码被公开传播 → 把那行从随机回复里删掉，后面的人领不到（已领的照样能用，拦不住）
- 泄露一批 → 补一批新编号，手里剩下的别再发
- 想追责 → 只能拿订单时间跟传播时间对

**号段**：`BZR-AF-2026-0001` 起，一批 20 枚。下一批从 `0021` 起，不复用旧号。
