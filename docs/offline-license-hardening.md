# 离线授权能防到什么程度

> 调研 + 落地方案（2026-11-03）。对象：bz-reader 的纯离线激活码。
> 相关：`docs/pricing-and-license.md` §11（五种手段对比）、`docs/trial-code-design.md`（联网核销方案，暂不启用）。

## 0. 一句话结论

离线没有「防住」，只有「把门槛抬高到大多数人懒得翻」。可设防的地方有六处：**码里、本地状态、时间、使用路径、分发、社会层**。其中 ROI 最高的是「码里写死到期日」和「一人一码 + 署名水印」，最不该做的是硬件指纹和代码混淆。

## 1. 先定威胁模型

| 谁 | 动机 | 你能做的 |
|---|---|---|
| 顺手转发给朋友的人 | 省几十块 | 水印 + 麻烦度，挡住大部分 |
| 把码贴到群里/闲鱼的人 | 引流、回血 | 一人一码 + 批次 + 到期日，缩小半径 |
| 会开 devtools 的人 | 白嫖 | 只能提高门槛，挡不住 |
| 做盗版分发的 | 卖钱 | 只能靠更新节奏和法律，挡不住 |

**目标不是「零盗版」，是「让 95% 的人觉得不如买」**。为 5% 的人给 95% 的正版用户加摩擦，是亏本买卖。

## 2. 业界怎么做的（样本）

| 产品 | 做法 | 关键细节 |
|---|---|---|
| **Bases Power Pack**（Obsidian） | Ed25519 离线验签，公钥内嵌，无账号无服务器 | 校验放在**渲染路径**上，不只是藏 UI；支付外包给 Lemon Squeezy / Gumroad |
| **Prose Lens**（Obsidian） | Ed25519 离线验签 | 把「不做任何网络调用，包括授权」写成卖点 |
| **highlight-inbox-synthesizer**（Obsidian，DEV 文章） | Ed25519 + tweetnacl，私钥只在作者密码管理器 | 免费层是**终身 3 次**，不是每月重置——「按月重置会让人等，终身上限制造决策点」 |
| **jinianri**（国产） | 设备指纹 → 人工发码 | ¥29.9 永久 + 48h 试用；指纹要用户手动复制 |
| **Keygen**（授权 SaaS） | 签名 license file，带 TTL（默认 30 天） | TTL 是为了「最终一致」：吊销/续期后旧文件最多 30 天失效；公钥必须硬编码进客户端 |
| **AveLynx / Spiralum** | Ed25519 license file + 硬件节点锁定 | 另有**单调水位线文件**：每次启动校验 `now >= watermark`，防时钟回拨 |

两个可以直接借的点：

1. **Keygen 的 TTL 思路**：离线凭证也该有「有效期」，到期重新验证。没有服务器时，「重新验证」只能是「重新输入码」。
2. **AveLynx 的水位线**：时间不是读一次就信，而是「只能往前走」。这比「检测回拨」更简单也更有效。

## 3. 六个可以设防的地方

### 3.1 码里（签名 payload）

能塞进签名、客户端改不了的东西：

| 字段 | 作用 | 挡住谁 |
|---|---|---|
| `exp` | 固定到期日 | 清缓存续命、重装续命、改本地时间（配合水位线） |
| `name` | 署名水印，设置页显示「本副本授权给 张三」 | 公开发布（丢脸）、闲鱼倒卖（可追溯） |
| `note` / `batch` | 批次号，知道哪一批泄露 | 定位泄露源 |
| `kind` | 通用码 / 付费码 / 试用 | 防止试用码被当买断码用 |
| `features` | 能力位（可选） | 将来做分级 |

**关键**：`exp` 必须是**固定日期**，不是「激活后 N 天」。固定日期没有本地状态可清——码到日子就死，`localStorage.clear()` 也换不来新的 7 天。

成本：签发脚本几行，客户端几行。伤正版：无（规则清晰）。

### 3.2 本地状态（存在哪、存什么）

现状（`src/data/entitlement.ts`）：

- 存在 `window.localStorage` 的 `bzs-entitlement-v1`：`installId` / `activeDays` / `license` / `token` / `lastSeenTs`。
- **只存码，不存结论**：`plan` / `exp` / `name` 每次从码里现解。改 localStorage 改不出永久授权。
- 启动时 `revalidateLicense()` 真验一次签名，假码清掉。

可以加的两件事：

**a. 多点存状态**（如果做「激活后 N 天」）

同一个 `startedAt` 写到三个地方，启动时取**最早**：

1. `localStorage`（跨 vault，重装插件不丢）
2. `IndexedDB`（同 origin，清 localStorage 不清它）
3. vault 里的一个文件（`.bz 阅读/.license-stamp`，跟着库走）

清一处不清全部，挡住「控制台一条命令」的懒人。换机器还是重置——这条挡不住。

**b. 水位线（单调时间）**

每次启动：`watermark = max(watermark, now)`，写回三处；校验 `now < watermark - 1h` 就判回拨。比现在的 `clockAnomaly` 更直接——现在的逻辑是「回拨超过 7 天或 3 次才作废」，太宽容。

注意：水位线文件如果放在同步目录里，多设备同步会互相打架（另一台机器时间慢就误伤）。要么只写本地不同步的位置，要么容忍 1 天误差。

### 3.3 时间

离线唯一的时间源是系统时钟。能做的：

- 单调水位线（上面）。
- 回拨阈值放小：`now < watermark - 1h` 就记一次异常，累计 3 次锁试用。
- 不要用「连续在线时长」这类需要后台计时的东西——插件随时会被关掉。

### 3.4 使用路径（校验放哪）

这是最容易被忽略、但性价比很高的一处。

**反面**：只在按钮上判断 `can('export')`，把按钮藏了。用户改一下 DOM 或直接调函数就绕过去了。

**正面**：把校验放在**产生价值的那一层**：

- `exportBookNotes()` 内部检查 `can('export')`，没授权返回空——不是靠按钮藏。
- 统计页的数据聚合函数内部检查 `can('stats')`。
- AI 调用入口内部检查 `can('ai')`。
- 多格式解析器入口检查 `can('fullFormats')`。

这样「删一个 if」不够，要删好几个地方。Bases Power Pack 说的 "enforced at render time, not just hidden in the UI" 就是这个意思。

成本：把 `requireCap` 从 action 层下沉到 data 层，约十几处。伤正版：无。

### 3.5 分发与版本

- **私有更新通道**：付费用户进私有 repo / 私有 release；泄露 = 踢权限。成本几乎为零（GitHub 权限），国内门槛是要装 BRAT。
- **版本闸门**：新版本引入新 schema / 新功能；旧版读到新数据提示升级。旧包是冻结快照，拿旧包的人永远落后。成本中等，副作用是旧用户被落下。
- **短期码 + 换码**：付费码 90 天有效，到期免费换新码。离线做这个很别扭（要人工发），除非有服务器——这也是为什么「短期码」通常和服务端一起出现。

### 3.6 社会层与产品

这部分不算「技术」，但效果往往比技术大：

- **水印**：设置页、关于页显示「授权给 张三 · 2026-11-03」。贴出去的人自己会掂量。
- **群规 / EULA**：写清楚「一人一码，禁止转售」，给踢人一个依据。
- **定价**：¥29–59 的区间里，「懒得找盗版」的人比想象的多。
- **免费层设计**：免费能完整读完一本书，付费买的是「把书变成资产」。免费层越可用，越少人去找破解。
- **终身额度而不是按月重置**：免费版导出 3 次（终身）比「每月 3 次」转化更好——按月重置会让人等。

## 4. 攻击面 × 防线矩阵

| 攻击 | 固定 `exp` | 署名水印 | 水位线 | 多点状态 | 使用路径下沉 |
|---|---|---|---|---|---|
| 转发码给朋友 | ❌ | ⚠️ 威慑 | — | — | — |
| 清 `localStorage` | ✅ 无效（码已死） | — | — | ⚠️ 部分 | — |
| 重装插件 | ✅ 无效 | — | — | — | — |
| 换 vault | ✅ 无效 | — | — | — | — |
| 拷库到新机器 | ⚠️ 码没过期就有效 | ⚠️ | ❌ | ❌ | — |
| 改系统时间 | ❌ | — | ✅ | — | — |
| 改 `data.json` | ✅ 无效 | — | — | ⚠️ | — |
| 打补丁 | ❌ | — | — | — | ⚠️ 要改多处 |

✅ = 有效挡住；⚠️ = 提高门槛；❌ = 挡不住。

## 5. 不该做的

| 手段 | 为什么不做 |
|---|---|
| **硬件指纹 / 节点锁定** | 政策敏感、隐私争议、换机客诉高；Obsidian 用户尤其反感「一个阅读器凭什么读我硬盘序列号」。而且客户端生成的指纹本来就可伪造。 |
| **代码混淆** | Obsidian 开发者政策明令禁止（"Obfuscate code to hide its purpose"）。 |
| **设备数上限** | 必须有服务端记账；离线做不到，硬做只会变成客诉。 |
| **反调试 / 完整性自校验** | 违反「代码可读」的精神，删几行就绕过，还可能误伤（比如用户用了代理、改了系统时间）。 |
| **把结论存盘** | 改一个字段就破解。只存码、结论现解——这条仓库已经做对了，别退回去。 |
| **联网心跳** | 阅读器断网不能用 = 不可接受；而且违反「本地优先」的产品承诺。 |

## 6. 落到 bz-reader：纯离线的推荐配置

### 6.1 码格式

```json
// 通用码：固定窗口，不是「激活后 7 天」
{ "v": 3, "kind": "universal", "id": "U-20261103-01",
  "exp": 1794288000000, "name": "", "note": "QQ群第1批" }

// 付费码：永久，一人一码
{ "v": 3, "kind": "paid", "id": "P-20261103-0001",
  "name": "张三", "exp": 0 }
```

- `exp` 是**发码时**定死的日期，客户端只判 `now < exp`。
- 通用码不存任何本地试用状态——没有状态可清。
- 付费码一人一码；泄露一枚只泄露一个人。

### 6.2 客户端

- `verifyLicense`：`kind === 'universal'` 且 `now < exp` → 直接放行，不联网。
- `entitlement`：不再需要 `token` / `redeem` 路径（代码留着，不接）。
- 设置页：`授权给 张三 · 群批次 A · 有效期到 2026-11-10`。
- 到期：高级功能锁，数据可读可导出（这条已经在做）。

### 6.3 水位线

- 三处存 `lastSeenTs`：`localStorage`、`IndexedDB`、vault 文件。
- 启动时 `now < max - 1h` → 记一次异常；累计 3 次 → 试用作废（付费码不受影响）。
- 只在「试用态」检查，别误伤付费用户。

### 6.4 使用路径

把 `requireCap` 从 `shell/actions.ts` 下沉到 `data/export.ts`、`ui/stats-panel.ts`、`data/ai.ts` 等产生价值的地方。约十几处，半天。

### 6.5 工作量

| 项 | 时间 |
|---|---|
| 固定 `exp` + 客户端放行 | 0.5h |
| 署名 / 批次显示 | 0.5h |
| 水位线（三处存 + 校验） | 2h |
| 使用路径下沉 | 3–4h |
| 测试 | 1h |
| **合计** | **约 1 天** |
