### Installation

Installation depuis le répertoire communautaire (visible une fois la première validation passée) :

1. Ouvrir **Réglages → Modules complémentaires** et désactiver le mode restreint.
2. Cliquer sur **Parcourir**, chercher **bz Reader** et installer.
3. Activer — une icône bz apparaît dans le ruban de gauche ; commencez par la bibliothèque.

Pendant la validation, ou si la recherche ne donne rien : ajoutez ce dépôt avec [BRAT](https://github.com/TfTHacker/obsidian42-brat), ou téléchargez `main.js`, `manifest.json` et `styles.css` depuis la Release, placez-les dans `<votre coffre>/.obsidian/plugins/bz-reader/`, puis activez.

### Langues de l'interface

L'interface suit la langue d'Obsidian, et vous pouvez aussi en choisir une parmi huit sous **Bibliothèque → Réglages → Interface** : 简体中文, 繁體中文, English, 日本語, Deutsch, Français, Español, Português.

Le changement s'applique immédiatement à l'interface ; les noms des commandes après un redémarrage d'Obsidian. Le chinois traditionnel n'est pas une conversion de glyphes du simplifié : c'est un pack distinct avec le vocabulaire de Taïwan (設定 / 預設 / 匯入 / 匯出 / 檔案). **Le journal des versions est l'unique exception** : il est écrit à la main à chaque publication et n'existe qu'en chinois et en anglais ; les six autres langues affichent les entrées anglaises.

### Fonctions Pro

L'édition de base est gratuite. Les fonctions Pro demandent une clé de licence ; le prix en cours figure sur la [page d'achat](https://wzyp.cn/shop/IFCEI5I3).

- La clé se saisit dans **Bibliothèque → Réglages → Licence**. Elle est vérifiée localement, sans appel réseau.
- Elle n'est liée à aucun nombre d'appareils : ressaisissez-la simplement sur un nouvel appareil.
- Une seule version couvre bureau et mobile — pas de second achat.

### Comment fonctionne l'IA

- Chaque livre conserve localement un **portrait** (découpages + vecteurs / résumés).
- Une question passe d'abord par le **routage**, puis par la **recherche hybride** ; seules les preuves dans le budget entrent dans le prompt.
- La réponse revient en SSE, puis fait l'objet d'une **vérification des citations**.

#### Pourquoi les plongements viennent de bz

- L'extension se distribue en trois fichiers (`main.js`, `manifest.json`, `styles.css`) et ne peut embarquer ni poids de modèle ni environnement d'exécution. Un petit modèle figé limiterait la précision de la recherche pour tout le monde.
- La couche de plongement est fournie par bz (Second Brain). Vous choisissez le modèle : un modèle local conséquent ou un service cloud. Plus la machine est puissante, plus le modèle peut être précis.
- Les segments du livre et les notes doivent partager le même **espace vectoriel** (les notes trouvées comptent aussi comme preuves). Un nom de modèle différent de celui de bz produisait autrefois des résultats **silencieusement erronés**.
- bz fournit et enregistre le nom du modèle ; un changement invalide les anciens portraits. Les vecteurs restent dans `portraits/` sur l'appareil.

#### Portrait et découpage

- `portraits/<id du livre>.json` : `plan / model / dim / chunkChars / overlap / blocks[] / overview / guides / done` ; chaque bloc contient `chapter / vec / digest / summary / text`.
- Vecteurs en **Float32Array** base64, similarité cosinus calculée localement, écritures atomiques ; cache **LRU** de 50 vecteurs de requête.
- Découpage aux limites de paragraphes, avec ajustement au début des chapitres.
- **A Recherche vectorielle** : 1000 caractères par bloc, chevauchement de 120, 8 blocs par lot. **B Compression d'information** : 8000 caractères par bloc, condensés par le modèle de dialogue, exclus de la recherche vectorielle.
- Un seul livre à la fois, indisponible sur mobile.

#### Recherche hybride et reclassement

- **Canal littéral** : bigrammes chinois avec **BM25** (k1 1,2 / b 0,75), champ « nom de chapitre » pondéré ×2,5.
- **Canal vectoriel** : requête reformulée, recherche de voisins, seuil absolu 0,2 / relatif 0,6.
- **Fusion RRF par rang** (k = 60) : le cosinus et BM25 ne sont pas comparables, on fusionne les rangs sans normaliser les scores.
- **Convergence adaptative** : plancher 3 / plafond 30 / rel 0,3 / abs 1e-4, déduplication par chapitre.
- **Extension aux voisins** : les blocs ±1 autour des trois meilleurs candidats entrent avec un poids de 0,85 ; **compensation du début de chapitre** conserve le premier bloc d'un chapitre trouvé.
- **Budget** : top 6 / 8000 caractères ; recherche sémantique inter-livres : 3 par livre, 20 au total.

#### Routage structurel, génération et vérification

- **Carte des chapitres** : une ligne par chapitre, numéros de section remplacés par leurs vrais noms, score littéral 3/1, « chapitre N » correspondance stricte, aucun appel de modèle.
- **Lecture du chapitre entier** : sommaire:texte 3:7, au moins 600 caractères par chapitre, troncature signalée ; pour une question sur tout le livre, `bookSpread` prélève un échantillon dans chaque chapitre.
- **Barrière anti-spoiler** : coupe après le dernier bloc du chapitre courant et vide la vue d'ensemble ; commune aux trois parcours et aux reprises, désactivée par défaut.
- **Prompt** : 8000 caractères de preuves et 6 derniers tours ; citations entre 「」 avec nom de chapitre.
- **SSE en flux** : `TextDecoder(stream:true)` pour les caractères UTF-8 coupés, délai mesuré entre octets, mise à jour du DOM à 80 ms, réponse partielle conservée.
- **Vérification des citations** : les passages de 4 à 80 caractères sont comparés aux preuves réellement envoyées (recouvrement de bigrammes ≥ 0,8), les courts doivent correspondre exactement ; 8 sources maximum avec saut au passage.

#### Parcours IA sans index

- Expliquer / traduire / résumer : seule la sélection est envoyée (résumé ≤100, explication ≤120 caractères).
- Suite : texte source ≤2000 caractères + éventuellement 3 blocs / 1200 caractères ; requête = 120 caractères avant le surlignage + question actuelle.
- Contexte de la barre latérale : 1200 caractères par élément, 6000 au total.

### PDF scannés : annoter et chercher

- **OCR** : le menu « Reconnaître les pages scannées » propose cette page / les 20 suivantes / tout le livre / réessayer les pages en échec. Traitement séquentiel, 20 pages par lot. Modèle de vision ou service OCR local / LAN (mobile : vision uniquement). Le traitement complet demande confirmation, car les pages sont facturées.
- **Résultat** : un fichier JSON annexe par livre, par défaut `bz-reader/storage/ocr/<id du livre>.json` (dossier de données modifiable) ; le PDF n'est pas modifié. Les résultats survivent au redémarrage ; les pages en échec sont conservées pour « réessayer N pages », sans nouvelle tentative automatique.
- **Couche de texte** : les lignes reconnues sont posées en transparence sur le scan, sélectionnables. Seules les pages avec des cadres de ligne permettent la sélection ; les pages avec texte brut sont lisibles et cherchables, mais non sélectionnables.
- **Annotations** : les pages OCR partagent surlignages, quatre couleurs, commentaires et wikilinks avec les PDF normaux ; ancre = « numéro de page + décalage de caractère dans la couche de texte ». Sans couche de texte, le glisser crée un rectangle, avec commentaires, liens et export en carte de citation ; le texte cité nécessite l'OCR.
- **Recherche** : la recherche littérale dans tous les livres et dans le PDF lit directement le JSON, sans reconstruction d'index. Un résultat saute à la page et dessine des rectangles sur la couche transparente ; 40 surlignages par page, 300 résultats au total et 50 par livre.
- **Recherche sémantique** : nécessite un portrait. Son texte vient de l'OCR page par page : l'OCR doit donc précéder la construction du portrait, sinon il faut reconstruire. Le portrait doit être terminé et le modèle de plongement correspondre. Un résultat sémantique n'a pas d'ancre exacte : à l'ouverture, une recherche textuelle est relancée avec l'extrait.

### Lecture à voix haute : fonctionnement

- **Texte** : EPUB / TXT utilisent le passage visible ou un chapitre entier ; PDF lit uniquement la couche de texte de la page courante, les pages scannées exigent d'abord l'OCR, et il n'y a pas de pré-génération par chapitre pour les PDF.
- **Trois moteurs** : voix système (hors ligne, sans cache ni préchargement), en ligne (endpoint officiel ou compatible OpenAI), service vocal auto-hébergé. Les réglages TTS sont indépendants des réglages IA ; sur mobile, le mode en ligne est imposé.
- **Découpage en phrases** : séparer narration et dialogue, puis couper aux signes de ponctuation ; cible 240 caractères, les phrases trop longues reculent à une virgule, les fragments courts sont fusionnés, les fragments uniquement symboliques ne sont pas lus. Voix système : 220 / 4000 caractères.
- **Lecture** : synthèse phrase par phrase avec enchaînement automatique ; 3 phrases préchargées (le service local prépare tout le chapitre), au plus 2 requêtes simultanées ; un changement de position n'annule que les requêtes périmées. Les phrases refusées sont ignorées, un échec de préchargement est retenté une fois en silence, les autres échecs s'arrêtent avec « Continuer l'écoute ».
- **Cache** : clé composée du livre + moteur + modèle + voix + texte, stockée localement ; un hit ne rafraîchit que l'horodatage. 300 Mo par défaut, réglable jusqu'à 2 Go.
- **Surlignage** : en ligne et local, chaque phrase est projetée sur le texte par une ancre, sans événement vocal ni minuterie ; l'audio hors ligne par chapitre utilise un axe temporel, la voix système un callback de début.
- **Pré-génération** : l'audio d'un chapitre est assemblé en un fichier avec une liste de temps et de plages d'octets par phrase ; écriture atomique et relecture de vérification. Six états (file / synthèse / assemblage / terminé / annulé / échec), sans estimation de durée, l'arrêt prenant effet aux limites de phrase ; le cache sert de progression, avec reprise ou reconstruction. Par chapitre : Pro ; tout le livre : uniquement avec un moteur local, pas sur mobile.
- **Écoute hors ligne** : copier le dossier complet (audio + manifeste) dans `bz-reader/offline/` du coffre. Un seul niveau est analysé, correspondance par titre puis identifiant de livre ; copier seulement les mp3 ne suffit pas. La lecture découpe selon les plages d'octets ou, à défaut, joue le chapitre entier avec un axe temporel ; un texte modifié est réaligné et le chapitre suivant démarre tout seul.
- **Reprise** : seule la dernière position est enregistrée localement à l'arrêt, à la granularité de la phrase. Restauration : même chapitre avec décalage → recherche dans tout le chapitre → début de page. La position ne suit pas sur un autre appareil.

### Accès réseau

Seules les fonctions d'IA et la liste des soutiens dans « Soutenir l'auteur » vont en ligne ; tout le reste fonctionne hors ligne.

- Les requêtes partent vers le point d'accès compatible OpenAI que vous configurez (votre serveur ou une API tierce). Le plugin n'a pas de serveur propre.
- La construction de l'index du livre envoie le texte par blocs à votre service d'embedding ; une question n'envoie que les quelques blocs retrouvés, plus le titre du livre, le nom du chapitre et les derniers échanges si nécessaire. Les vecteurs et l'index restent dans le dossier du plugin et ne sont jamais téléversés.
- Les embeddings viennent du plugin bz (second cerveau) : sans lui, pas de recherche vectorielle, seulement la voie des points clés condensés.
- Votre clé d'API est stockée avec le reste des réglages dans `data.json`, dans le dossier du plugin. Elle n'est jamais envoyée à l'auteur ; elle ne part que vers le point d'accès que vous avez configuré, en en-tête de requête.
- À l'ouverture de « Soutenir l'auteur » (ou du journal des modifications), une liste publique de soutiens est chargée : le même fichier JSON statique sur GitHub et Gitee en même temps, la première réponse l'emporte. Seule cette liste est récupérée, sans aucune donnée personnelle ni statistique. La liste est mise en cache localement ; si les deux sources échouent, « Impossible de charger la liste » s'affiche avec un bouton Réessayer. La liste est publique et identique dans les deux plugins.

### Questions fréquentes

- **Quels formats ?** EPUB et TXT d'emblée ; mobi, azw3, fb2, BD et PDF avec Pro.
- **Des conflits avec d'autres plugins ?** Le lecteur est une vue native d'Obsidian et le sommaire un onglet du panneau latéral gauche. Les surlignages se copient en liens Markdown avec repère qui reviennent au passage exact — aucun index séparé n'est construit.
- **Changer d'ordinateur ?** Le coffre emporte la bibliothèque, la progression et les annotations. Ressaisissez la clé de licence sur le nouvel appareil.
- **Faut-il payer à nouveau sur mobile ?** Non. Une seule version couvre bureau et mobile.
