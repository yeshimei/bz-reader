### インストール

コミュニティディレクトリからインストールします（初回審査の通過後に表示されます）。

1. **設定 → コミュニティプラグイン** を開き、制限モードを解除します。
2. **閲覧** をクリックし、**bz Reader** を検索してインストールします。
3. 有効にすると左リボンに bz アイコンが現れます。本棚から始めてください。

審査中で見つからない場合は、[BRAT](https://github.com/TfTHacker/obsidian42-brat) でこのリポジトリを追加するか、Release から `main.js`・`manifest.json`・`styles.css` をダウンロードして `<保管庫>/.obsidian/plugins/bz-reader/` に置き、有効化してください。

### 表示言語

表示言語は Obsidian の言語に従い、**本棚 → 設定 → 表示** から手動で選ぶこともできます：简体中文、繁體中文、English、日本語、Deutsch、Français、Español、Português。

切り替えると表示はすぐ変わります。コマンド名は Obsidian の再起動後に反映されます。繁体字は簡体字の字形変換ではなく、台湾の用語を使う別パックです（設定 / 預設 / 匯入 / 匯出 / 檔案）。**更新履歴だけは例外**で、リリースごとに手書きのため中国語と英語の 2 版のみ、他の 6 言語では英語の項目を表示します。

### プロ版について

ベーシック版は無料です。プロ版の機能にはライセンスキーが必要です。価格は[購入ページ](https://wzyp.cn/shop/IFCEI5I3)をご覧ください。

- キーは **本棚 → 設定 → ライセンス** に入力します。検証はローカルで行われ、通信しません。
- デバイス数に紐づきません。新しい端末では同じ場所にもう一度入力してください。
- デスクトップとモバイルは同じビルドなので、1 回の購入で両方使えます。

### AI の仕組み

- 各書籍はローカルに**画像（portrait）**（チャンク＋ベクトル／要約）を持ちます。
- 質問はまず**ルーティング**され、**ハイブリッド検索**を経て、予算内の根拠だけが prompt に入ります。
- 回答は SSE でストリーミングされ、その後に**引用の照合**を行います。

#### なぜ埋め込みを bz に借りるのか

- プラグインは `main.js` / `manifest.json` / `styles.css` の三ファイルで配布され、モデル重みや推論ランタイムを同梱できません。固定の小モデルを内蔵すれば、全員の検索精度がそこで頭打ちになります。
- 埋め込み層は bz（Second Brain）が提供します。モデルは利用者が選べるため、計算資源が許せば重いローカルモデルやクラウドサービスで精度を上げられます。
- 書籍とノートは同じ**ベクトル空間**に置く必要があります（ノートの命中も根拠になる）。モデル名が bz と違うと、以前は**気づかないまま誤った結果**が出ていました。
- モデル名は bz が注入して画像に記録し、変更時は古い画像を無効にします。ベクトル自体はローカルの `portraits/` に残ります。

#### 画像とチャンク分割

- `portraits/<書 id>.json`：`plan / model / dim / chunkChars / overlap / blocks[] / overview / guides / done`。各ブロックは `chapter / vec / digest / summary / text` を持ちます。
- ベクトルは base64 の **Float32Array** で保存し、コサイン類似度はローカルで計算、書き込みは原子置換。検索ベクトルは 50 件の **LRU** キャッシュ。
- 分割は段落境界を基本にし、章の冒頭で切りを調整します。
- **A ベクトル検索**：1 チャンク約 1000 字、重なり 120 字、8 チャンクずつ埋め込みへ。**B 情報圧縮**：1 チャンク約 8000 字をチャットモデルで要約し、ベクトル検索には使いません。
- 同時に構築できるのは一冊だけ。モバイルでは利用できません。

#### ハイブリッド検索と再ランク

- **字面チャネル**：日本語・中国語の二字組 **BM25**（k1 1.2 / b 0.75）、章名フィールド重み ×2.5。
- **ベクトルチャネル**：クエリを改変して近傍検索、絶対 0.2 / 相対 0.6。
- **RRF ランク融合**（k = 60）：コサインと BM25 は尺度が違うため、正規化せず順位を統合します。
- **適応的な絞り込み**：floor 3 / ceiling 30 / rel 0.3 / abs 1e-4、章ごとに重複排除。
- **近隣拡張**：上位 3 候補の前後チャンクを重み 0.85 で追加。**章頭補償**として命中章の先頭チャンクを残します。
- **予算**：上位 6 件 / 8000 字。横断的な意味検索は 1 冊 3 件、全体で 20 件まで。

#### 構造ルーティング、生成、照合

- **章レベルマップ**：1 章 1 行の要約、節番号を実名に補正、字面の章選択重み 3/1、「第 N 章」は完全一致、モデル呼び出しなし。
- **章全体読み**：目次:本文 3:7、1 章 600 字以上、超出分は截断表示。全体に関する質問は `bookSpread` で各章から均等に抽出。
- **ネタバレ門**：現在の章の最後のチャンクで切り、概観をクリア。三経路とフォローアップの補充段落で共通、既定はオフ。
- **prompt**：根拠 8000 字＋直近 6 ターン。引用は「」で囲み章名を添えます。
- **SSE ストリーミング**：`TextDecoder(stream:true)` で漢字の分断を処理、バイト間隔でタイムアウト、80ms スロットルで DOM 更新、途中までの回答を保持。
- **引用照合**：4〜80 字の引用を実際に送った根拠と二字組一致度 ≥0.8 で比較し、短い引用は完全一致。根拠は最大 8 件、本文へジャンプできます。

#### 索引なしの純 AI 経路

- 説明／翻訳／要約：選択範囲のみ送信（要約 ≤100 字、説明 ≤120 字）。
- フォローアップ：原文 ≤2000 字＋任意の同書 3 チャンク / 1200 字。クエリは「強調箇所の前 120 字＋今回の質問」で指代を補います。
- サイドバーの上下文：1 件 1200 字、合計 6000 字まで。

### スキャン PDF の書き込みと検索

- **OCR**：「スキャンページを認識」メニューに現在ページ／次の 20 ページ／全体／失敗ページの再試行。1 ページずつ順番に処理し、20 ページずつ。ビジョンモデルまたは自前／LAN の OCR サービス（モバイルはビジョンのみ）。全体処理はページ課金のため確認が出ます。
- **結果**：1 冊につきサイドカー JSON を 1 つ、既定では `bz-reader/storage/ocr/<書 id>.json`（データフォルダ変更可）。PDF 本体は変更しません。再起動後も残り、失敗ページは「再試行」用に記録されます。自動再試行はありません。
- **文字レイヤ**：認識した行を透明で選択可能なレイヤとしてスキャン画像に重ねます。行ボックスがあるページだけ選択でき、文字だけのページは読める・検索できるが選択はできません。
- **書き込み**：OCR ページも通常の PDF と同じ線引き、四色、メモ、ウィキリンクを使えます。アンカーは「ページ番号＋文字レイヤ上の文字オフセット」。文字レイヤのないページは矩形選択になり、メモ・リンク・書摘画像の書き出しは可能ですが、引用文は認識済みの文字が必要です。
- **検索**：全ライブラリの字面検索と PDF 内検索はサイドカー JSON を直接読み、索引再構築は不要。命中箇所はページへジャンプし、透明レイヤに矩形ハイライトを描きます。1 ページ 40 箇所、全体 300 件／1 冊 50 件まで。
- **意味検索**：画像（portrait）が必要です。画像本文はページごとの OCR 文字から作られるため、**OCR を先に**行わないと新しい文字は検索できません。後から OCR したページは再構築が必要です。画像が完了し、埋め込みモデルが一致していることも条件です。意味命中には正確なアンカーがないため、開くとスニペットで再び全文検索を行います。

### 読み上げの仕組み

- **テキスト**：EPUB / TXT は表示中の段落または章全体。PDF は現在ページの文字レイヤのみで、スキャンページは先に OCR が必要、章単位の事前生成はありません。
- **三つのエンジン**：システム音声（完全オフライン、キャッシュも先読みもなし）、オンライン（公式または OpenAI 互換エンドポイント）、自前の音声サービス。読み上げ設定は AI 設定と独立し、モバイルはオンライン固定です。
- **文分割**：地の文と会話を分け、句読点で分割。1 文の目安は 240 字、長すぎる場合は読点などの柔らかい境界で切り、短すぎる断片は前の文に統合、記号のみの断片は読み上げません。システム音声は 220 / 4000 字です。
- **再生**：1 文ずつ合成して再生し、終わると次へ。既定で 3 文を先読み（自前サービスは章全体を準備）、同時リクエストは最大 2 件。位置を変えても先読みは止めず、古いリクエストだけを取り消します。審査で拒否された文は飛ばし、先読み失敗は黙って一度だけ再試行、それ以外の失敗は「続きを聴く」を残して停止します。
- **キャッシュ**：「書籍＋エンジン＋モデル＋音色＋文字」をキーにローカル保存し、命中時は時刻を更新するだけ。既定 300 MB、最大 2 GB まで調整可能。
- **ハイライト**：オンライン／ローカルでは音声イベントや計時ではなく、文のアンカーを本文に映射してページ上で強調します。非対応時はオーバーレイに退避。オフラインの章単位音声はタイム軸、システム音声は開始コールバックを使います。
- **事前生成**：章の音声を一つのファイルに連結し、文ごとの時刻とバイト範囲のマニフェストを添えます。書き込みは原子置換で、書き込んでから読み戻して検証。進行状態は待機／合成／パッケージ／完了／キャンセル／失敗の六態、時間予測はしません。停止は文の境界で効き、キャッシュがそのまま進捗になり、続きから也可能です。章単位は Pro 機能、 book 単位はローカルエンジンのみ、モバイル不可。
- **オフライン再生**：音声とマニフェストの**フォルダ全体**を库内の `bz-reader/offline/` に入れます。プラグインは一段だけ走査し、書名→書 ID の順で照合。mp3 だけでは見つかりません。設定から「再スキャン」もできます。再生はマニフェストのバイト範囲で切り出し、範囲がなければ章全体をタイム軸で再生。本文を編集しても自動で位置合わせし、再生が終わると次の章へ進みます。
- **再開**：最新の位置だけを停止時にローカルへ保存し、単位は文。復元は「同じ章の元位置 → 章全体を検索 → ページ先頭」の三段階。別端末には引き継がれません。

### ネットワークアクセス

ネットワークを使うのは AI 機能と「作者を支援する」の支援者名簿だけです。それ以外は完全にオフラインで動作します。

- リクエストは、設定で入力した OpenAI 互換のエンドポイント（自前のサーバーでも第三者 API でも可）に送られます。プラグイン独自のサーバーはありません。
- 全書インデックスを作るときは、本の本文を分割して埋め込みサービスに送ります。質問時は検索でヒットした数ブロックだけを送り、必要に応じて書名・章名・直近数ターンを添えます。ベクトルとインデックスはプラグインフォルダに保存され、アップロードされません。
- 埋め込みは bz（セカンドブレイン）プラグインが提供します。入っていないとベクトル検索は使えず、要点圧縮の方式だけになります。
- API キーは他の設定とともにプラグインフォルダの `data.json` に保存されます。作者に送信されることはなく、設定したエンドポイントへのリクエストヘッダーとしてのみ送られます。
- 「作者を支援する」ダイアログ（および更新履歴）を開くと、公開の支援者名簿を読み込みます。GitHub と Gitee 上の同じ静的 JSON を同時に要求し、先に返った方を使います。取得するのはこの名簿だけで、個人情報の送信やアクセス解析は行いません。名簿は端末にキャッシュされ、両方の取得元が失敗したときは「読み込めませんでした」と再試行を表示します。名簿は公開データで、2 つのプラグインで表示内容は同じです。

### よくある質問

- **対応フォーマットは？** EPUB と TXT はすぐ読めます。mobi・azw3・fb2・コミックと PDF はプロ版です。
- **他のプラグインと衝突しますか？** 読書画面は Obsidian のネイティブビュー、目次は左サイドバーのタブです。ハイライトは位置情報つきの Markdown リンクとしてコピーでき、クリックすると元の一文に戻ります。別途インデックスは作りません。
- **PC を買い替えたら？** 保管庫を同期すれば本棚・進捗・注釈もついてきます。プロ版は新しい端末でキーを再入力してください。
- **モバイルで別途購入が必要？** いいえ。1 つのビルドでデスクトップもモバイルも使えます。
